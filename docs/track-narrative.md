# 路线说明与形象标签自动生成

## 生效与触发

服务端 `TrackNarrativeService` 通过 scheduler 后台发现可生成的轨迹，读取详情/列表不调用 AI。默认每分钟扫描最多 200 条已有地理索引，每轮最多调用模型 3 次，按游标轮转；这是后台巡检，实际等待时间取决于轨迹量和生成队列，并非上传接口即时生成。

只处理公开、已结束、有原始轨迹地址、有效简化索引和方形预览图的记录。首次启动持久保存激活水位，不自动生成水位前未修改的历史记录。水位后的上传/修改、投稿变化在巡检中被发现；已纳管轨迹的标题、统计、预览地址、已通过投稿、景区摘要、简化点、模型或规则版本变化会重新生成。生成字段和更新时间不参与输入指纹，避免写回再次触发。

首次发现输入版本后等待至少一分钟；景区识别未完成最多额外等到首次发现后十分钟，之后允许缺景区生成，景区稍后补齐会重新触发。输入只采用当前落库数据；原始文件与索引的异步更新可能先后到达，后续索引变化会再触发。

## 输入与输出

输入为标题、位置、运动类型、距离/时长/累计爬升、已有简化点中的七个有序海拔样本、已有主景区摘要和可信的已通过投稿。海拔样本不代表极值或精确坡度，不推断停顿原因。投稿含 DevMode、投稿测试、审核链路等明显测试标识时整条排除。文字字段截短，模型只收到摘要和一张方图，未发送原始 KMZ 或全部 GPS 点，也不追加联网搜索。

优先 square_day，缺失时 square_night，要求实际图片为 64～2048 像素正方形、最多 4 MiB。标题仅是形象候选，轨迹整体轮廓须支持；没有标题提示也独立判断。只有明确且积极/中性的形象才能输出；不明确或冒犯性形象留空。模型按提示判断相似度和适宜性，服务端要求两个判断字段并据此清空标签，不能将此视为独立人工审核。

说明自然介绍路线特色、运动强度与有证据的路况，最多 200 字符，不冒充亲身体验。只替换 auto/ai 来源说明，写入 description_source=ai；人工说明保留。形象仅在原本为空或仍等于上次 AI 写入值时更新，保留后续人工改动。写回采用条件更新避免覆盖生成期间的编辑。

景区、运动类型标签仍从已有数据生成，颜色沿用既有 labels 配置，不调用 AI。客户端重新读取详情后获得更新后的 description、shape_label、labels。

## 调度、预算与恢复

需 SCHEDULER_ENABLED=true、TRACK_NARRATIVE_ENABLED=true、可用 MOONSHOT_API_KEY、持久数据库及预览缓存；数据库降级内存时不启用外部生成。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| TRACK_NARRATIVE_ENABLED | true | 自动生成开关 |
| TRACK_NARRATIVE_MODEL | kimi-k2.6 | 模型 |
| TRACK_NARRATIVE_CRON | @every1m | 调度间隔 |
| TRACK_NARRATIVE_DAILY_BUDGET | 100 | 北京时间每日调用次数上限；非正值回退 100 |

复用 track_place_records 的 narrative:scan / narrative:track:<ID> 命名空间保存水位、游标与版本状态，复用 track_place_api_usage 的 kimi_track_narra 计数，预算与景区调用分开。全局租约十分钟、每轮超时八分钟；单次模型 HTTP 超时 150 秒，max_tokens=4096。每日预算限制调用次数而非精确 token 或金额。

每个输入版本最多三次尝试，失败退避；下载失败不计模型调用预算。成功结果先缓存再写回，写回冲突可以复用；异常崩溃在供应商成功而结果尚未落库的窗口仍可能重复调用。失败上限后同版本暂停，输入版本变化重新开始。任务不创建历史批量回填入口。

## 验证与发布边界

本轮 go build ./... 通过；遵循项目约定未新增或执行自动化测试，未实际调用生产模型验证此任务。代码尚未部署，线上不会因本地修改开始生成；部署前可用 TRACK_NARRATIVE_ENABLED=false 保持关闭。
