# 路线说明与形象标签自动生成

## 生效与触发

服务端 `TrackNarrativeService` 通过 scheduler 后台发现可生成的轨迹，读取详情/列表不调用 AI。默认每分钟扫描最多 200 条已有地理索引，每轮最多调用模型 3 次，按游标轮转；这是后台巡检，实际等待时间取决于轨迹量和生成队列，并非上传接口即时生成。

只处理公开、已结束、有原始轨迹地址、有效简化索引和方形预览图的记录。首次启动持久保存激活水位，不自动生成水位前未修改的历史记录。水位后的上传/修改、景区关联和投稿变化在巡检中被发现；首次扫描未变更的历史轨迹只持久保存事实基线，不调用模型，后续事实变化才纳管，单独升级模型/规则不会批量回填这些历史记录。已纳管轨迹的标题、位置/城市、统计、预览地址、已通过投稿、景区摘要/分类、简化点、模型或规则版本变化会重新生成。统一 labels 的运动类型、精品状态、主景区（含等级）、人工图案新增/修改/移除也参与事实指纹；颜色不参与，不因渲染 labels 或打开页面调用 AI。

首次发现输入版本后等待至少一分钟；景区识别未完成最多额外等到首次发现后十分钟，之后允许缺景区生成，景区稍后补齐会重新触发。输入只采用当前落库数据；原始文件与索引的异步更新可能先后到达，后续索引变化会再触发。

## 输入与输出

后台手动形象生成使用 `PreviewShape → GenerateShape` 专用调用，关闭思考模式、temperature=0.6、max_tokens=8192；仅发送标题、基础统计、一张方图与有效经验，不生成 description、不发送投稿及景区长文。8类检查、最多3个候选、recognition_status、appropriateness、decision_summary 经严格校验后作为 diagnosis 返回；不明确/不适宜时标签为空但依据保留。最近成功结果含模型、时间和输入版本，存于 `narrative:shape-preview:<ID>`，后台详情只展示仍匹配当前输入版本的结果，不覆盖轨迹。达到输出上限作为明确错误提示，不伪装成没有形象。后台保存标签仍需用户点击保存。自动任务及学习复核继续使用组合生成流程，不能把专用诊断的结果当作自动任务效果证明。

规则 v3 将动物/生肖、花草、地标建筑、数字、地图、人物头像、节庆生日及组合图案作为同等优先组逐类检查，无内部排名，不要求动物候选。优先组检查完再比较其他类别；比较整体覆盖、关键部位及牵强程度，有歧义仍可留空。保持单次调用，线上响应协议不增加分类诊断字段。

说明规则 v5：输入为标题、位置/城市、运动类型、距离/时长/累计爬升、已有简化点中的七个有序海拔样本、统一 labels 的语义投影（type/code/name，不发送颜色）、已有主景区摘要/分类和可信的已通过投稿。海拔样本不代表极值或精确坡度，不推断停顿原因。投稿含 DevMode、投稿测试、审核链路等明显测试标识时整条排除。文字字段截短，模型只收到摘要和一张方图，未发送原始 KMZ 或全部 GPS 点，自动任务不追加联网搜索；后台手动说明入口另见下节。

优先 square_day，缺失时 square_night，要求实际图片为 64～2048 像素正方形、最多 4 MiB。标题仅是形象候选，轨迹整体轮廓须支持；没有标题提示也独立判断。只有明确且积极/中性的形象才能输出；不明确或冒犯性形象留空。模型按提示判断相似度和适宜性，服务端要求两个判断字段并据此清空标签，不能将此视为独立人工审核。

形象规则 v2 按一笔画、简笔画识别，优先考察动物、花草、地标建筑、数字、地图轮廓（如中国地图）和人物头像，不限于这些类别。先看整体轮廓，再核对关键部位及相对位置；允许道路折线、比例简化、少量绕行及不影响判断的图标遮挡，不要求写实或细节齐全。可旋转观察，但不能任意删线、补造特征或把底图/图标当形象部位；严重遮挡、仅局部像或整体不支持时留空。使用普通名称，不猜动物品种，也不据建筑形象推断实际途经该地标。规则入口为 [track-shape-label skill](../skills/track-shape-label/SKILL.md)，共享正文由该目录的 `rules.go` 嵌入并在 `internal/service/kimi_track_narrative.go` 使用；头像不猜具体身份，地图形象不代表实际地域覆盖；保持一张图、一次调用，不新增候选轮询或联网搜索。规则版本进入输入指纹，部署后已纳管轨迹会按既有队列与日预算重新判断，人工修改保护保持不变。

说明用第一人称向朋友介绍路线，把数据转成有依据的感受总结：路线紧凑或舒展、短途走动或需要专门安排、起伏对体力的影响与走向节奏。通常80～160字、最多200字符；正文不罗列距离、爬升、用时、速度等运动数字，也不改成汉字继续复述。保留必要地名和图案名称，缺少资料可写短。第一人称不等于声称实地走过，不编风、花香、路感、遮阴或景色等现场见闻；不把自驾爬升当成运动体力强度、不把含停留的用时当作普遍节奏、不从七个海拔样本编完整坡段。不宣称新手友好或轻松安全，景区介绍不代表全程实况。自动任务只替换auto/ai来源，写为ai，人工说明保留；形象仅在原本为空或仍等于上次AI值时更新，写回采用条件更新。


AI 自己写入的图案会传给模型作参考，但不进入触发指纹；同次生成的说明可采用本次明确识别的图案，避免写回标签后再付费调用。人工图案及人工清空用 `shape_locked` 约束说明，不因重新识图而宣传其他图案；它们参与指纹并触发说明更新。默认说明本身、更新时间和动态经验均不参与事实指纹。

景区、运动类型标签仍从已有数据生成，颜色沿用既有 labels 配置，不调用 AI。Android 普通上传不携带默认说明，详情为空时不再本地兜底；已有服务端说明继续显示，投稿说明独立保存，投稿专用辅助生成另行定义。客户端重新读取详情后获得更新后的 description、shape_label、labels。

形象规则 v2 同时支持节庆、生日及组合图案（生肖与年份、蛋糕与数字等）。多个明确主体可合成一个短标签；只有一个完整显著主体可辨时只保留该主体，不猜测其余部分。数字按轨迹笔画读取，不依标题或生肖历法补全，也不自动解释为年龄；轨迹自身画出的数字/文字与需排除的地图文字区分。保持一个 `shape_label`、一张图、一次调用。

## 后台单条说明试写

共享轨迹编辑器的“路线说明”旁提供“AI 联网填写”，调用 `PreviewDescription → GenerateDescription`，先用城市和主景区/位置检索最多5条地点背景，再结合轨迹事实与一张方图生成200字以内说明。说明规则与自动任务共用 `trackDescriptionRules`；专用说明调用关闭思考模式，temperature=0.6，不产出图案，已有形象（含无标签）是说明唯一图案来源。网页只作参考，重名/无关资料不可采用，不把其他路线的体验套给本轨迹。返回实际检索参考来源供核对，不代表逐条引用。

该入口绕过历史水位，需公开、已完成、有效索引、原始文件与方图；无位置/主景区时先补全。一次搜索（30秒）与一次模型生成共享270秒整体超时、5分钟扫描租约，预留1份 narrative 日额度，不自动重试。成功只在独立候选区展示说明和来源，原说明不变，不排队历史任务。管理员可编辑候选，点击“一键代入并保存”即通过独立PUT保存说明，不依赖详情保存按钮；source_version与仓储CAS防止覆盖变化后的资料，只标记manual/v0及更新说明/时间，不改其他草稿或形象。自动任务不覆盖确认后的人工说明。接口、权限、来源展示与草稿保护见 [后台协议](api/admin-tracks.md#路线说明与-ai-联网填写)。

## 调度、预算与恢复

自动巡检需 SCHEDULER_ENABLED=true、TRACK_NARRATIVE_ENABLED=true、可用 MOONSHOT_API_KEY、持久数据库及预览缓存。手动说明/形象生成不依赖前两个开关，允许先关闭自动任务逐条试写；其余配置仍须就绪，数据库降级内存时不启用外部生成。

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| TRACK_NARRATIVE_ENABLED | true | 自动巡检开关，不关闭后台手动入口 |
| TRACK_NARRATIVE_MODEL | kimi-k2.6 | 模型 |
| TRACK_NARRATIVE_CRON | @every1m | 调度间隔 |
| TRACK_NARRATIVE_DAILY_BUDGET | 100 | 北京时间每日调用次数上限；非正值回退 100 |

复用 track_place_records 的 narrative:scan / narrative:track:<ID> 命名空间保存水位、游标与版本状态，复用 track_place_api_usage 的 kimi_track_narra 计数，预算与景区调用分开。全局租约十分钟、每轮超时八分钟；单次模型 HTTP 超时 240 秒，max_tokens=8192（思考与正文共用上限，不代表每次实际消耗）。后台手动识别请求总超时 270 秒，租约仍为五分钟。每日预算限制调用次数而非精确 token 或金额。

每个输入版本最多三次尝试，失败退避；下载失败不计模型调用预算。成功结果先缓存再写回，写回冲突可以复用；异常崩溃在供应商成功而结果尚未落库的窗口仍可能重复调用。失败上限后同版本暂停，输入版本变化重新开始。任务不创建历史批量回填入口。

## 验证与发布边界
人工修正学习入口为 `internal/service/track_shape_learning.go`。后台保存形象变化（含清空）后记录最新反馈，AI 未配置或记录失败返回 `learning_warning`，不把已保存的轨迹伪装成保存失败。普通客户端修改不触发学习。现有索引巡检每轮最多复核一条，与生成共享每轮3次、每日调用预算；一张图、一次请求，失败最多3次退避。未公开或无索引的轨迹不主动调用模型。

复用 `track_place_records` 中的 `narrative:shape-feedback:<ID>` 保存每条轨迹最新修正与复核，`narrative:shape-memory` 保存最近8条支持案例；短租约防止旧复核覆盖新修正，全局扫描租约串行更新经验。生成最多引用4条经验，依据与经验各最多100字符，引用前核对源仍公开、标签与图片未变。改标、换图、下架使旧经验停用；不因经验变化批量重跑。人工清空同样保护。后台显示复核依据与经验，不输出旧模型未记录的推理；无图像支持的标注保留人工值但不吸收为经验。

固定 skill 规则与动态经验层共同作用，是提示词经验积累，不是模型训练或生产源码自改。基础规则及适宜性要求优先，源码规则仍按案例复盘后正常构建部署。

## 当前验证范围

源码编译不能证明模型实际措辞和识图效果；功能及文案需用真实轨迹人工验收。自动化测试、实际模型调用和部署结果以当次交付报告为准。部署前可用 TRACK_NARRATIVE_ENABLED=false 保持关闭。

Kimi 公共请求方法按模式统一设置温度：即时模式 `thinking.type=disabled` 搭配0.6，思考模式使用1.0，调用方不能再独立传入冲突组合。依据 [Moonshot 官方模型说明](https://huggingface.co/moonshotai/Kimi-K2.6)。非200响应只记录已知参数类别，不输出供应商可能回显的原始输入/图片或密钥。

供应商失败提示：识别 `exceeded_current_quota_error` / insufficient balance 后明确提示补充 API 账户余额。独立搜索返回403且没有可读错误时，仅追加一次最长5秒的只读余额查询；可用余额≤0提示余额不足，其余提示检索被拒绝、检查账户状态和搜索权限。不在余额查询失败时推断欠费，不自动重试、切换服务商或伪造离线生成结果。供应商原始错误可能包含账户标识或输入，仅记录状态和已知错误类别。

## AI 使用管理接入

自动说明/图案、手动说明、手动图案及人工修正学习均进入持久化 AI 任务账本，搜索、生成与必要诊断逐次记录；手动候选与实际采用分开。新增按功能暂停、日请求预算与并发限制，中断传播至HTTP context及保存前检查，同输入版本的人工中断不被巡检立即重启。保留本章的全局扫描租约、共享日生成额度和人工保护。纯查询不生成内容，历史调用不推算Token。详见 [AI 使用运行说明](ai-usage.md)。
