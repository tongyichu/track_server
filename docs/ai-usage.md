# AI 使用记录与运行控制

后台入口 `/admin/ai_usage.html`。协议及字段见 [admin-ai](api/admin-ai.md)，页面复用 Tabler、共享 shell、AdminUI 和 AdminChartStyle，图表异步加载，列表不依赖图表/配置。实时任务及配额区默认每5秒刷新，统计及当前页记录每15秒刷新，可关闭；页面隐藏停止轮询，离开释放定时器、请求和图表。配置草稿不因查询刷新丢失，CAS冲突可显式重新载入配置。

## 接入范围

| feature | 调用来源 | provider 请求 |
| --- | --- | --- |
| track_auto | 上传后的首次生成、已保存标题/位置/运动/labels/景区/投稿/预览变化、规则/模型版本变化、失败后巡检重试 | 组合说明与图案生成 |
| track_description | 共享轨迹详情“AI 联网填写” | 地点检索、说明生成，必要时账户诊断 |
| track_shape | 共享轨迹详情手动形象识别 | 图案专用生成 |
| shape_learning | 人工改标/清空后的后台学习复核 | 组合生成中的复核 |
| scenic_description | 景点页手动生成、创建时缺简介补充、新识别景点的后台补充 | 搜索及景点介绍生成 |

统一链路：业务校验/当前快照 → Manager.Begin（持久任务、可取消排队、功能槽位）→ ai.Observe（预留日请求次数、记录每次请求和usage）→ 结果验证 → 保存前取消校验 → 原有业务CAS → Finish。手动候选与真实业务写入分开，生成成功不等于已采用。完整输入、请求体/图片及隐藏推理不进入日志，详情只提供有界摘要与业务输出。

## 持久化与故障

新增独立 `AIUsageRepository`，MySQL/Mongo/memory提供同等CRUD/CAS、筛选计数、分页及统计语义。MySQL启动创建 ai_usage_tasks / ai_usage_state，mysql.sql同步；Mongo建立索引。业务连接成功但AI表初始化失败时不启用付费调用，不改业务仓储降级策略。内存实现用于本地一致性，不在业务降级内存时启用供应商请求。

任务表：可筛选标量、payload和有界summary。列表按页只取summary，统计流式读取匹配summary，空间为功能/模型/日期分组，不读取完整业务结果、不逐条查业务对象。策略与模型价格独立CAS。每个功能的AIControl文档保存跨进程执行槽位、北京时间请求预算，冲突重读后重试；策略单独revision避免心跳引起无关编辑冲突。

租约30秒，每2秒续租并读取中断/暂停；租约丢失停止后续调用与写回。自动恢复器每15秒将过期未结束任务标记interrupted或cancelled，不在GET里写任务，不自动重新调用。重启后通常在租约到期及下一轮恢复扫描内更新旧运行状态；网络中断或崩溃后可能无法取得供应商消耗，显示未知。

任务取消在CAS中登记，写回前切换saving形成边界，saving期间拒绝中断。取消不会撤回已发送的请求和费用。自动任务中断按feature/object/input-version抑制，同版本后续巡检不马上重启；后台手动重试重新读取资料并保留原任务关联。暂停自动功能会停止未进入saving的执行，恢复后可继续，不形成永久中断标记。

## 预算、费用与提醒

每日请求上限默认0（不限），后台可保存0～100000；只有正数才执行日上限校验。次数仍按实际请求步骤预留，包括搜索/生成/必要账户诊断；正数上限通过跨进程CAS防超额。预留后取消、网络失败或结果未知不返还预算，防止反复取消绕过上限。实际请求数另记录，发送前取消标记not_sent。按功能限制执行中的业务任务并发；原路线/学习仍遵守全局扫描租约，旧共享100次生成额度及其环境配置已停用，不再有后台不可调整的隐藏次数限制。

Token取响应usage，不以max_tokens代替实际消耗。缺失用量与未知费用保留null；成功但输出校验失败仍计已发生用量。价格由管理员配置，支持输入、缓存命中、输出和独立搜索价格，不内置未经核对的现价；新价格只用于后续请求，每次记录保留价格版本与当时单价快照。费用为估算，不能代替供应商账单；失败/取消无法取得用量时不推定免费。

统计按任务创建日归属（跨日任务请求亦归任务日），每日请求预算按发起日。后台提醒包含暂停状态、当天预留预算达到80%、已知Token/费用超过提醒线，以及今天任务失败率较高（至少3项失败且≥20%）或平均耗时≥60秒（至少3项结束）。提醒只显示在后台，未增加邮件/外部通知。Token与费用阈值为提醒，仅设置为正数的请求上限与并发是硬限制。不限时不显示预算耗尽提醒。

本次未修改AGENTS.md：既有根规则及后台局部规则已覆盖新增路由、三仓储、权限审计与验证方式，业务入口已补入其指向的流程和协议文档。

本次用户授权解除日额度：启动时逐功能CAS将既有daily_requests设为0，并在同一AIControl文档保存daily_limit_migration=1，保留原请求计数、租约、暂停状态及提醒配置。该迁移每功能只应用一次，多个进程启动不会覆盖标记后的管理员修改；未来重启保留后续手工设置的正数预算。初始化失败则阻止新付费调用，并在启动日志明确提示。迁移不发起AI请求、不重置历史消耗。

首次上线不迁移旧调用次数为Token或账单，不回填历史任务，不主动生成内容。任务记录从真实接入后开始。

## 扩展与验证

新增模型/供应商应复用 Spec + Observe，使用实际供应商及模型名称，再实现对应usage/价格解析；仅支持当前已接入moonshot，不提供页面任意输入密钥或切换未实现供应商。所有新AI入口需接入Manager，不能绕过持久记录、预算、中断和业务人工保护。

权限分为ai_usage查看、ai_tasks操作、ai_settings配置，源业务写权限仍决定能否重试/采用；继承后台同源与审计。既有账号不自动扩大权限。

按仓库约定只做Go构建、JS语法和静态自查，不新增/运行测试，不启动环境，不调用AI试跑。功能和视觉效果由用户验收。部署还需按既有发布流程完成，源码构建通过不代表已上线。

## 配额呈现与前端初始化

配额管理前置到历史统计上方，直接展示今天已计用量、当前日上限、剩余、百分比、有效运行槽位和最近调整人；不限显示“不限”，不会把null剩余额度画成0。用量按计数器口径（含预留/失败），统计区继续展示实际请求及Token，两者边界在页面说明。配置操作由独立quota接口更新，保留其他草稿、计数和并发/暂停设置；不同窗口修改由CAS拒绝覆盖。

配额使用独立只读轻量接口，不等待价格/历史统计，轮询原位更新配额数字，不替换正在编辑的弹窗。刷新失败保留上次数据并提示，可手动重试。统计和当前页任务记录也自动更新，避免只刷新实时任务后已完成调用长期不可见。

修正AI页初始化时误用bootstrap.Modal的问题；本项目内置Tabler只暴露tabler.Modal，引用错误会在首次加载时阻止后续查询。此次以生产AI账本的只读聚合确认已有请求与Token已保存，没有补造调用或发起AI试跑。
