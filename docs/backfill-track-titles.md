# 存量轨迹时间标题回填

入口：`cmd/backfill-track-titles`。这是一次性 MySQL 运维工具，不修改业务 HTTP 接口、数据库表结构或投稿审核状态。

## 选择和生成规则

- 默认只选择未删除、已结束且标题仅包含日期/时间的轨迹。支持 Android 常见中文、英文、数字日期格式，以及旧版日期与时间之间的“• / ·”分隔符；无法识别的格式保留原值。
- 默认保留人工描述性标题，包括“日期 + 描述”的标题。用户明确要求清理日期前后缀时，可用 `-include-dated-titles`：保留已有路线描述，移除开头/结尾的日期；“日期 + 地区”优先使用记录中的具体地点，没有具体地点时保留原地区信息。日期出现在描述中间的标题不选择。
- 没有可复用投稿标题且运动类型不属于现有五种内置类型时，保留原值，不推测运动类型。
- 优先采用同一轨迹、同一作者已有的有效投稿标题。
- 没有投稿标题时，按 Android `TrackSubmissionDraftFactory` 的中文规则，使用具体位置、运动类型和路线形态生成。
- 环线要求距离至少 500 米、首尾距离不超过 `min(150 米, 总距离 × 5%)`，且围成面积至少为 `总距离² × 1%`，与 Android 保持一致。仅首尾接近的原路折返不会被命名为环线。
- 远端只有一个 `locate_addr`，不推测终点地址。轨迹点不可用时只生成“某位置周边某运动”；没有具体位置时使用“距离 + 运动类型 + 路线”，距离缺失则用“运动类型 + 路线记录”，不再生成年月日兜底标题。
- 回填时对历史地址额外做保守清理：“已定位 / 未知位置”等状态、纯门牌号、经纬度坐标和 Plus Code 不作为具体地点；括号被截断时只保留其前面完整的地点名。这是针对历史 `locate_addr` 的清理，不更改不含日期前后缀的描述性标题。
- 使用服务器已缓存的原始轨迹，复用现有 JSON/GeoJSON/KML/KMZ 解析器，不调用逆地理编码。计划中的 `geometry_known=false` 表示无法确认形态。

## 运行环境

在拥有实际服务环境变量的机器上执行，复用 `internal/config.Load()`。必须显式配置 `MYSQL_DSN`，禁止降级到内存仓储，也不运行建表/迁移。

配置文件及密码不能提交到仓库或直接写进命令行。可由现有容器、systemd 环境或受保护的配置注入环境变量。

```bash
go build -o build/backfill-track-titles ./cmd/backfill-track-titles
```

## 先生成计划

```bash
./build/backfill-track-titles -plan /secure/path/title-plan.json
```

可选 `-user-id 123` 限定作者，`-max-changes 20` 限制本次候选数量。`-include-dated-titles` 扩展选择范围，包含导入标题的日期前后缀和上次回填的“日期 + 运动类型 + 记录”兜底标题；此开关仅用于生成计划。计划文件保留作者、轨迹 ID、新旧标题和来源，权限为 `0600`，已有文件不会被覆盖。

默认从 `<LOG_DIR>/static/raw_tracks` 读取缓存，或用 `-raw-track-dir` 指定已有缓存目录。默认不下载缺失的原始轨迹；在服务器内网需要补下载时，使用 `-download-raw` 并配置既有 OSS STS 凭证和 `OSS_INTERNAL_ENDPOINT`，不允许公网回退。下载/解析不可用时会使用不推测形态的保守标题。

生成计划只查询数据库，不修改数据库记录。计划绑定 MySQL 网络类型、地址和数据库名的 SHA-256 指纹，不含连接密码。生成和应用时需使用同一连接地址。

## 应用已核对的计划

```bash
./build/backfill-track-titles \
  -apply-plan /secure/path/title-plan.json \
  -result /secure/path/title-result.jsonl
```

应用前验证整个计划，拒绝错误数据库、重复 ID、不含日期前后缀的旧标题，以及长度不合法或仍含日期前后缀的新标题。逐条仅更新 `track_records.title` 和 `updated_at`，同时匹配轨迹 ID、作者和旧标题，并确认轨迹未删除、未重新开始录制。旧标题使用 MySQL 二进制比较，预览后的人工改名优先，更新不会覆盖其他轨迹字段。

结果文件记录每条 `updated` / `skipped`。重复执行原计划时，已修改记录不再匹配旧标题，会被跳过。执行中断可能已有部分成功，不能把整个批次视为已回滚；保留原计划和结果，使用新的结果文件继续执行原计划。

原计划是标题修改前的备份。需要回退时按实际成功记录匹配当前新标题后恢复旧标题，避免覆盖后续人工编辑；不要直接无条件批量覆盖。
