# 自动景区识别（普通服务版）

## 入口与范围

`internal/service/track_place_service.go` 负责识别；`track_place_provider.go` 封装高德和 Google；`internal/repository/track_place*.go` 提供 MySQL、Mongo、内存实现。`track_place` 定时任务默认每分钟运行，受 `SCHEDULER_ENABLED` 控制。它独立于上传、地图查询和每日路线相似度聚合，不在这些请求中调用外部地图服务。

第一阶段解决自动地点关联与地图聚合，不自动编造景点介绍，不调用需要另开权限的 AOI 多边形接口。客户端既有 `scenic_spot` 气泡和点击下钻可复用。旧 `catalog.json` 的景区介绍 H5 保留兼容；开启新流程后，手工景区矩形不再作为自动归属依据，行政区目录仍提供区县兜底。

### 后台景点删除（归档）

后台景点详情底部的“删除景点”经确认后调用既有 `POST /admin/api/scenic-spots/:spot_id/status`，请求为 `{"status":"archived","expected_version":<详情版本号>}`，需要景点模块写权限。成功返回更新后的景点，默认目录、统计和客户端不再展示；只归档景点，关联轨迹、图片文件、内部关系与历史审计保留。不新增物理删除接口或数据库结构。

按钮只在编辑有效的已有景点时显示，新建与只读详情不显示。请求期间禁用保存和重复删除；版本冲突返回409，保留表单并提示重新打开确认，不自动覆盖资料或重试。取消确认不提交任何修改；成功后关闭详情并刷新列表、统计，清除当前已删除景点的 URL 深链。

### 后台图片自动保存

图片卡片取消左右移动按钮，只保留拖动排序；在缩略图与说明输入框之间显示像素尺寸和文件大小。上传响应新增只读`data.image_info={width,height,size_bytes}`；历史本站图片通过受鉴权静态资源的`photo_info=1`读取，详情见[后台资源接口](admin-routes.md)。图片文件信息不写入景点照片数组或版本基线。

图片上传支持JPG、PNG、WebP，单张8MiB以内、尺寸不超过12000×12000；服务端识别实际图片内容，WebP按原格式保存并用于预览，不强制转为JPG或PNG。

景点详情上传后自动经 `PUT /admin/api/scenic-spots/:spot_id/photos` 保存图片关联，删除/排序即时提交，说明失焦提交。请求 `{expected_version,photos}` 仅替换图片和更新版本/操作人，通过既有仓储CAS及后台写权限、同源和审计；不保存名称、简介等文字草稿，也不触发来源核验或等级采集。30张上限和说明255字校验沿用原规则。版本冲突返回409，保留本地图片修改供核对，不自动覆盖其他管理员操作。上传文件接口 `?draft=1` 仍只暂存，旧无draft调用行为保留。

新建景点先保存基本资料，成功后保留详情并开放图片上传。共享编辑器串行保存快照，上传和保存中禁止关闭/切换；未保存失败项可重试或放弃本地图片修改。文字“保存修改”只处理文字表单，图片操作不点亮该按钮；保留未完成图片修改时，文字保存成功也不关闭详情。省市宣传图片采用相同交互，协议见 [地区图片自动保存](api/regions.md#图片自动保存)。

### 高德景点图片本地存储

`internal/service/scenic_spot_photo_store.go` 在新建、编辑、独立图片保存以及供应商资料同步的写流程中，将高德图片下载并压缩为本站 WebP。沿用城市宣传图的 libwebp 参数 `-q 75 -m 6 -sharp_yuv -af -metadata icc`，先归一化 EXIF 方向，再等比缩放：横图（含正方形）宽1024px，竖图高720px，不裁切、不拉伸。城市图和已有本站上传图不在本次回写范围，Google图片同时通过受限的googleusercontent.com域名白名单同步到本站；其他外链不自动下载。

源图只接受高德/高德地图域名的HTTPS地址及同范围重定向，单张最多8MiB、边长12000px、总像素2400万；全进程最多2个下载压缩任务，同源并发去重，单图处理20秒、每次图片数组处理25秒。结果以“原图地址＋编码规则”的SHA-256作文件名，原子保存到 `<LogDir>/static/scenic_spots/amap/<hash>.webp`，重试复用完整成品。图片ID、顺序、说明、作者和已有来源不变；没有来源时记录原图地址。后台和客户端分别沿用后台会话及业务JWT读取，不新增公共图片路由，读取目录/详情/图片信息不触发外部下载。

既有 `POST /admin/api/scenic-spots/provider-content/backfill` 在检查“资料已同步”前独立处理已有高德外链，因此已完成资料同步、缺少有效来源标识的有效景点也能补图；图片处理只使用现有地址，不额外查询POI。响应增加 `photos_cached`（本批成功保存关联的图片数）及 `photos_failed`（下载压缩失败张数），后台每次扫描1处并显示图片进度。新同步图片失败保留原链接供下轮重试；已有图片替换只在文件完成后按版本CAS保存，冲突不覆盖管理员编辑。新建/编辑/图片保存遇到图片处理失败时不提交本次修改，已压缩成品留作重试缓存。页面自动保存成功后接纳服务端的本站地址，同时保留正在输入的说明，不把旧外链写回。

容器运行层安装 Debian `webp`；二进制部署需提供PATH中的 `cwebp`，缺失时图片处理明确失败，不伪造成功。内存降级不启用该外部下载能力。不新增表或仓储接口，三种仓储继续使用既有景点JSON及版本CAS。

## 识别依据

1. 只扫描公开、结束、有原始 GPS 的轨迹空间索引；按轨迹 ID 游标每批最多50条，进度持久化。历史数据自动进入扫描，不需要客户端重传 GPS。
2. 轨迹折线按累计距离取5个等距内部采样点，避免只看起点、中心点或静止点密度。少于100米的折线不识别。关联以稳定轨迹 ID 保存，不随路线组重建丢失。
3. 国内使用高德普通逆地理编码 `extensions=all`。接纳风景名胜/公园（typecode 11xxxx）与自然地名（1904xx，山峰/湖泊等）类型，AOI `distance=0` 作为该采样点在区域内的证据。规则 v3：至少2/5个采样点命中同一 AOI，不再要求连续，选命中数唯一最高者；并列不强选。源摘要未变的旧版 matched 主归属保留。
4. 国外使用 Google Places New Nearby Search（tourist_attraction/park/national_park/museum/natural_feature/campground），只请求 ID、名称、类型、位置及父地点 ID。结果保存为 `nearby` 关联；如果返回的上级地点 ID 唯一命中地区目录中可选节点的 `google/place_id` 外部映射，则给地点填入该节点的内部 `region_id`，多城市命中时留空。景点自身 Place ID 不当作城市 ID。邻近搜索与 `viewport` 均不能证明轨迹位于景区内，因此本阶段不以 Google 附近结果替换行政区/网格气泡。跨国内外边界路线也保留兜底。
5. 国内无采样主归属且没有并列冲突时，补充“围着景点”的判断。`track_place_ring.go` 从完整 GPS 中寻找回到此前位置附近的近闭合子路径，而不是要求整条轨迹首尾闭合；子路径长度至少100米、闭合点距离不超过子路径长度15%（下限25米、上限150米）、围合面积至少400平方米，并排除跨度超过1度或包围框面积超过200平方公里的路线。空间索引简化折线只用于预筛；符合条件后读取完整原始GPS、按源坐标转换为GCJ02，再做点在多边形内判断，拒绝距边线3米以内的不确定点，不能直接用包围框。
6. `track_place_search.go` 用高德普通 `/v3/place/polygon`（矩形召回、types=110000|190400），每页25条、最多4页；超过100候选不强选。圈内同时存在父景区和其子地点时按 provider parent ID 合并，父景区优先；合并后只有一个独立景区才自动归属。围住多个独立景点时状态保存为 `candidate`，只进入管理后台候选队列，不随机取最近者，也不下发客户端主景点。自交环线使用奇偶规则，净面积不足时保守跳过。山系/湖泊等开放自然地物多为点 POI、边界不稳定：即使几何上唯一命中，也只降级为 `candidate` 进入人工确认队列，不自动归属（Google natural_feature 同理，降级后为 unmatched）。供应商分类在写入内部目录时归一为景区/公园/山系/湖泊展示口径。
7. 记录 `primary_method=sampled_aoi/enclosed_poi`；环绕证据为 `enclosed=true`，新增关系使用 `kind=enclosed_poi`。这是采样或环绕 POI 点的业务推断，不是供应商景区边界、精确覆盖比例或景区内里程，也不声称环绕轨迹进入景区。国外本阶段仍只保留附近关联。

## 坐标

空间索引统一为国内 GCJ02、境外保持 WGS84数值的地图接口口径，原始GPS文件不变；支持 WGS84、GCJ02、BD09输入，空字段沿用历史 GCJ02约定，未知坐标系拒绝生成索引。

大陆覆盖判断使用 `internal/maparea/mainland.json` 的省级多边形，而非将印度、越南等也框进去的经纬度矩形。文件由 DataV.GeoAtlas `https://geo.datav.aliyun.com/areas_v3/bound/100000_full.json` 筛选大陆31个省级行政区域生成，保留多边形和内洞；仅用于地图服务路由与坐标转换，不作为景区边界。数据源、授权和边境精度沿用项目行政区域数据的维护要求。

旧的非 GCJ02索引在扫描时从完整原始 GPS 重建，不能仅变更坐标标签。之后路线组的中心和范围由既有聚合任务更新。

轨迹 `coordinate_system` 描述上传文件而非本地录制会话；Android 导出归一化为 WGS84，创建/首次上传同步传 WGS84，KML Document 增加 `track_export_coordinate_system=WGS84`。索引从实际解析成功的同一份 KML 读取标记。旧记录仅在 source_tag 为空、声明 GCJ02，且具有本项目 `ff52ffd6` / `GxTrackExtendedData` / `gx:Track` 特征时修正为 WGS84；不推断早期空声明或无显式标记的人工导入。三种仓储通过 `TrackRawCoordinateWriter` 按 ID、旧声明、源地址、来源和状态 CAS 更新，只改声明与更新时间。v1 已完成景区记录升级时检查一次原生 GCJ02/WGS84 导出并重建索引（WGS84 也用于重试声明已修复但索引写失败的情况），源变化后重新识别；路线组中心/范围由既有聚合任务刷新。

## 持久化与并发

- `track_place_records` / Mongo同名 collection 保存 `match:<track_id>` 任务结果、`place:<内部地点ID>` 共享资料、`request:<证据版本>:<provider>:<坐标>` 点查询缓存、`ring:<证据版本>:amap:<源摘要>:<页码>` 环内候选缓存，以及扫描游标/租约。地点内部 ID 由 provider + provider POI ID 确定，跨轨迹共享。扫描游标按判定规则版本隔离为 `scan_cursor:v<规则版本>`，规则升级后自动从头重扫，不覆盖旧版本进度。
- 结果含源折线摘要、规则版本、关联方式和采样计数。提交前重新比较索引来源及公开状态，防止旧任务作用于已改变或已删除的轨迹。
- 高德成功结果一次完成、长期复用：`matched`（有主要景区）、`candidate`（围住多个独立景点，待后台确认）和 `unmatched`（查询完成但没有主要景区）均不因时间到期重新识别，包含完全没有候选的结果。高德共享地点资料同步长期保存；旧版本已成功的数据按同样规则读取，不在升级时重新调用。GPS 源摘要或主动升级的识别规则变化仍会使旧结果失效；普通标题、文案更新不触发重算。
- 判定规则 v3 与证据版本 v1 分离，源摘要与旧点查询 key 保持兼容。源未变的 v1/v2 matched/unmatched 直接复用完整 Relations 重判，不重调5个点；旧正例保留、未命中项可按近闭合子路径补环内搜索。`evidence_complete` 使环内搜索遇到额度/临时失败时保留采样证据；新规则成功后仍一次完成。列表/详情接受源匹配的 v1～v3 正例。
- 扫描任务、单轨迹和同一查询均有数据库租约；多进程共享预算。实例内也禁止同任务重入。单轮上限在占用查询租约前检查，失败/额度不足也释放持有的查询租约并保留缓存内容。
- `track_place_api_usage` 按供应商、北京时间自然日持久化实际请求计数；重启不重置。失败请求也计数。默认每轮最多10次外部请求，串行间隔至少500ms，HTTP超时6秒，单轮任务最长90秒。
- 请求级无结果缓存最多24小时；它和已完成的轨迹业务结果是两个层次。只有暂时失败退避重试，凭证/供应商限流错误对该供应商暂停1小时；配置正数日上限时额度耗尽次日继续。默认高德不设日上限，Google 保留20次日上限。
- 请求缓存、供应商暂停记录和 Google 内容仍按有效期下发并分批清理；高德共享地点资料（包含旧版带到期时间的记录）排除在清理范围外。新长期结果在 MySQL 中 `expires_at=NULL`，Mongo/内存使用零时间；配置 TTL 不影响已完成的高德轨迹结果。
- 调度日志中的 `reused` 表示复用已完成结果，没有外呼；`skipped` 表示样本不足/过短，`unconfigured` 表示对应供应商尚未配置或跨服务范围，均不冒充成功。

## 地图接入

路线组仍只保留一个用于地图聚合的 `area_id`，区县归属可以由已有区域目录独立计算。后台只在代表轨迹仍匹配时更新 `area_id`，不覆盖路线组名称、成员或人工投稿资料。每日重建路线组时，批量读取稳定轨迹关联重新绑定。

地图区域接口按既有 `area_id` 聚合；新的 `place-amap-*` ID 对应共享地点，返回 `area_type=scenic_spot`、景点名称、`place_provider`、`place_match_method=track_relation`（可包含采样与环绕归属）。气泡范围仍为所属路线组的范围，不能被当成景区真实边界。每个路线组只计一次。未命中时为区县或网格。

`GET /track-map/groups/:group_id/detail` 可选增加 `nearby_places`（最多3条），只读取有效本地结果，不产生外部请求；本阶段不增加景点介绍正文或客户端附近景点展示页。

普通轨迹详情及全部轨迹摘要通过 `TrackService` 装饰 `primary_scenic_spot`。新目录中 active 景点使用内部 `SCP-*` ID；旧地图气泡和未迁移轨迹继续使用 `place-*` ID，两种 ID 口径不得混为同一键。轨迹主景点到目录的稳定关联存于 `track_scenic_spot_links`，按页批量读取；客户端列表和轨迹详情只读目录中状态为 active 的内容及本站图片，不调用供应商。后台自动匹配结束后，由同一后台扫描流程创建有效景点/关联；存量由景点管理页分批回填。回填遇到无有效来源 ID 的轨迹时，强制刷新坐标查询缓存并调用既有地图匹配链路，遵守供应商每日预算和每轮十次真实请求上限；Google nearby 结果只有同一地点至少命中五个采样点中的三个、且无并列时才作为主景点。轨迹详情不再实时查询来源或补图；Google Place ID过期核验移到需要补图的后台任务中。照片下载压缩完成后由目录保存本站地址，保留作者/来源，不向客户端返回未同步的供应商外链。客户端上传图片属于自有内容，经业务 JWT 读取。后台 API、发布/审核、改绑、合并拆分及审计细节见 `internal/admin/AGENTS.md`；业务响应协议见 `docs/api/track.md`。

主景点目录由 `scenic_spots` 自有内容记录、嵌入来源 ID、`track_scenic_spot_links` 关联和 `scenic_spot_audit_logs` 操作流水组成。内部 ID 为随机稳定 ID，不复用。合并时轨迹关联与来源 ID 并入目标，源记录标为 merged 并保留跳转；拆分为所选轨迹创建新景点并改绑。存量回填只复制供应商身份标识，创建有效景点；运营可编辑名称、分类、坐标、简介与自有图片，客户端只展示 active 景点；存量 draft/published 在仓储初始化时迁为 active，历史审计记录保留。Google Place ID由需要补图的后台流程按既有有效期核验；客户端不再临时请求媒体，后台同步后的本站图片保留来源与作者。当前后台供应商资料同步会将文字、图片引用与高德明确的景区等级保存到目录；持久化范围按适用账号授权执行。

运营页 `/admin/scenic_spots.html` 展示有效景点数量、已关联轨迹覆盖、每日供应商调用趋势和高调用景点排行。`scenic_spot_provider_usage` 只存 provider、操作类型、日期、请求数、成功数和失败数；从统计能力上线后开始累计，不回填历史请求。已关联内部景点的详情、图片和来源 ID 核验请求可按内部景点归因；存量轨迹应先运行后台回填，坐标识别扫描不纳入单景点排行。该数据用于安排自有资料维护，不包含供应商响应内容。

## 配置

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `TRACK_PLACE_ENABLED` | `true` | 自动识别开关；内存降级时强制不调用外部服务 |
| `TRACK_PLACE_CRON` | `@every 1m` | 后台扫描周期 |
| `AMAP_REST_KEY` | 已有配置 | 高德 Web服务 Key；缺失时沿用既有 `AMAP_WEB_KEY` / `AMAP_KEY` 兼容配置，但仍必须是有效的 Web服务凭证 |
| `AMAP_SECURITY_JS_CODE` | 空 | 管理后台交互景点地图使用的高德 JS API 安全密钥；与 `AMAP_WEB_KEY` 配套，仅经已登录后台配置接口下发 |
| `TRACK_PLACE_AMAP_DAILY_BUDGET` | `0` | 高德每日请求上限；默认0表示不设日上限，正数表示按该值限制 |
| `TRACK_PLACE_CACHE_HOURS` | `168` | 高德请求级缓存有效期，最大720小时；不再用于让成功的轨迹结果/共享景区资料到期重跑 |
| `GOOGLE_PLACES_API_KEY` | 空 | Google Places API New 服务端 Key，不读取 Android SDK Key |
| `TRACK_PLACE_GOOGLE_CACHE_HOURS` | `0` | 默认不持久化 Google地点内容，因而默认不运行该供应商查询；只有取得适用的暂存许可并显式配置有效期后启用，最大720小时 |

Google Places 查询不设应用侧每日预算或单轮请求数上限；真实配额和拒绝响应由 Google API 管理。Google 标准 Places 权限不意味着可创建永久名称/坐标库；Place ID 可以长期保存，但其他内容应遵守适用授权。无 Key、无授权缓存配置时，现有地图兜底可继续使用，不阻止服务启动。Key不下发客户端、不写进查询错误或日志。

## 后台候选入口与缺项筛选

景点管理页移除全局“景点识别候选”面板。候选在共享轨迹详情弹窗顶部展示，轨迹列表和景点相关轨迹入口均可访问；只读账号可看，轨迹可操作账号可确认或忽略。单条读取使用 `GET /admin/api/tracks/:track_id/place-candidates`，原 `/admin/api/place-candidates` 队列 API 保留为兼容入口，确认和忽略仍沿用既有接口并归属轨迹权限。读取继续校验源摘要、规则版本和可索引条件，只查缓存，不触发供应商识别。

轨迹列表新增 `missing=any|place_candidate|scenic_spot|description|city|previews`，依次对应任意缺项、待确认景点、未关联景点、缺简介、缺城市、缺预览图。条件参与总数和分页；当前有效候选 ID 批量取自既有队列，景点关联由自有目录查询，四张预览中任意缺失视为不完整。未关联景点也包含正常的非景区轨迹。完整后台协议见 [admin-tracks.md](api/admin-tracks.md)。

## 人工验收方式

默认只做 `go build ./...`，不主动运行接口测试或额外消耗供应商额度。人工验收时：

1. 在开发/部署环境设置 Web服务 Key、每日预算和 `SCHEDULER_ENABLED=true`；观察 `[scheduler] track_place` 计数。先用少量已知公园内与园外的公开轨迹。
2. 在 `9 < zoom <= 11` 查看对应区域气泡，确认多数采样点在公园内的路线出现景点名称，附近路过的路线仍在区县/网格；继续放大后能打开原路线组。
3. 检查 `track_place_api_usage` 的 `provider/usage_day/used`。重复查看地图不增加计数，重启不清零，额度耗尽后无继续外呼。
4. 检查一次后台扫描后再重建路线组，景区关联仍保留；删除/改成私密的轨迹不会新增识别结果。普通 API不提供任务运行或凭证修改入口。
5. 对同一条 WGS84/GCJ02输入及国外轨迹检查底图对齐；地图缩放和语言切换不改变景区身份。
6. 已完成的高德结果超过旧有效期后仍复用；有景区、无景区两种成功结果都不增加 API 使用量。失败/未完成项仍能续跑，请求级缓存过期也不会让已完成轨迹重跑。
7. 规则升级后人工核对2/5非连续命中、最高票并列，以及仅在 bbox 内但在折线外、单景区围合、父子景点、多独立景区、未闭合路线与候选截断；额度/临时失败后能续跑且保留采样证据。
8. 原生旧 GCJ02 声明仅符合导出特征才修复，人工导入及早期空声明不被推断；原文件字节不变，空间索引重新转换到地图坐标。普通列表/详情仍只读数据库，无供应商调用。


## 景区等级采集与下发

等级入口为 `internal/service/scenic_spot_grade.go`，使用现有高德 Web 服务 Key、日配额与景点调用统计，不增加配置项或定时任务。只对有效高德来源按相同 POI ID 调用 `GET https://restapi.amap.com/v5/place/detail?id=...&show_fields=business`，读取 `business.keytag` 的明确等级标签，例如“5A景区”“AAAAA级旅游景区”，统一为 `1A` 至 `5A`。同一返回存在矛盾等级时留空；不解析 rating、酒店星级、名称、简介，不继承父景点等级、不使用 AI 猜测。Google 来源暂无 A 级采集。

新建及修改来源的后台保存会先尝试采集，再随同一版本保存并返回，等级查询失败不阻止其他资料保存。轨迹识别自动创建的新景点在落库后异步采集。存量复用 `POST /admin/api/scenic-spots/provider-content/backfill?limit=5&cursor=...` 分页补采：原文字、图片已同步或缺少旧资料来源的记录仍独立检查等级，响应新增 `grades` 为本批补齐的等级数量；等级请求失败计入 `failed`，继续原有文字图片同步。仅 active 景点采集。高德调用使用 operation=grade 归因；成功命中/无等级结果均缓存，失败后续同步时重试，重新核验来源可重置自动采集状态。每条等级请求最多 15 秒。

保存字段如下，MySQL 沿用 `scenic_spots.data_json`，Mongo 使用同名 BSON 字段，内存实现沿用 JSON 深拷贝；不新增 SQL 列或表，也不改仓储接口。

| 字段 | 含义 |
| --- | --- |
| `scenic_grade` | 可选字符串，标准值 `1A`、`2A`、`3A`、`4A`、`5A`；未知/清空时省略 |
| `scenic_grade_source` | 自动来源 `amap:<POI ID>` 或 `manual`；没有高德来源时可为空 |
| `scenic_grade_status` | 未采集时空；`synced` 已取得等级，`unavailable` 查询成功无等级或无有效高德来源，`failed` 查询失败，`manual` 人工维护 |
| `scenic_grade_checked_at` | 最近采集或人工修正的时间 |

后台详情选择等级后沿用 `PUT /admin/api/scenic-spots/:spot_id` 的 `{expected_version,spot}` 保存。例如 `spot.scenic_grade="4A"`；清空传 `""`，旧请求省略保留原值，`null` 或非法值返回 400。来源/状态/时间为服务端托管，不能通过请求伪造；人工更改或清空标记 manual，后续自动采集不会覆盖。替换有效高德来源会清除原自动等级并重新采集；人工维护保持不变。自动补采只合并等级字段，并使用版本 CAS，不能覆盖同时发生的后台编辑。

客户端发现景点列表及轨迹详情/摘要 `primary_scenic_spot` 下发可选 `scenic_grade`，例如 `"scenic_grade":"5A"`。这些读取只查询目录，不调用供应商；没有值时隐藏等级，不能等同于官方“未评级”。景区详情页在标题旁展示等级标签；轨迹标签的 scenic_spot.name 由 API 组装为“景点名·5A”，中间是 U+00B7 居中点，客户端直接消费 labels，不重复拼接。

高德字段参考：[POI 2.0 官方文档](https://lbs.amap.com/api/webservice/guide/api-advanced/newpoisearch)。接入前只读确认了故宫的 v5 文本搜索和相同 ID 详情均返回 business.keytag=5A景区，v3 没有等级。该采集结果来自供应商标签，不代表本地独立核验了最新官方评级。

## 景点图片独立巡检

scenic_photos每分钟运行，沿用SCHEDULER_ENABLED和已启用的地点服务，且必须有持久景点仓储、TrackPlaceRepository与PhotoStore；内存降级不注册。每轮最多扫描100个active景点、处理2处待同步项，整轮100秒，2分钟全局租约和逐景点租约通过现有track_place_records的scenic:photos:scan:v1及scenic:photos:work:<ID>持久化，跨进程互斥、重启继续游标。到末尾重新轮转，新增及存量缺图自然入队，不由用户列表/详情读请求入队或调用供应商。状态按页批量读取，冷却项不逐条抢租约。

任务只迁移已保存的受支持外链，或在相册为空且未标记人工编辑时从有效来源补图；不改名称、简介、位置、人工照片内容或顺序。AMap沿用本站WebP缓存；Google只允许HTTPS的googleusercontent.com及其子域，重定向同样受白名单、443端口、无用户凭证约束。保留8MiB、12000边长、2400万像素、EXIF方向校正、下载并发2和25秒单次相册处理限制，源地址与编码规则哈希去重、原子落盘。未支持外链保持后台资料，App不把其当作本站图片。

供应商请求失败、下载失败、版本冲突按5分钟指数退避，最长320分钟；有效空图片结果负缓存24小时，来源/相册发生变化后重新判定。下载部分成功可以先保存本站图片，失败项保留待重试，客户端只显示已完成部分。完全未取得本站图且外链重试失败时，未人工编辑的相册会重新查询来源获取新媒体地址，避免反复使用失效链接；来源刷新无图不会清空已有待处理资料。供应商返回后重新读最新景点，照片事实/来源变化、归档/合并时不写回；仅文字等无关字段变化时基于重读的最新记录合并照片并CAS保存，复用既有仓储版本CAS；失败不覆盖人工资料。任何照片显式编辑由photos_edited保护，包括清空，旧数据不猜测历史手动操作。

此次只改变景点图片同步和客户端读取行为，不调用AI、不迁移轨迹GPS或更改鉴权。原后台人工同步接口继续可用，保留同样的人工相册保护。根与admin的AGENTS已覆盖后台任务、仓储CAS、只读不回填及静态资源边界，无须修改规则文件；任务和协议细节记在本节。
