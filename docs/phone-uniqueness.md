# 手机号唯一性与存量处理

手机号是账号的唯一登录凭据。当前接受去除首尾空白后的 11 位、以 1 开头的数字；不接受其他国家区号或分隔符格式。短信发送、短信登录、注册和绑定共用 `models.NormalizePhone`。未绑定手机号使用空字符串，允许多个第三方账号未绑定。

## 写入边界

- MySQL `users.phone_key` 为 `NULLIF(TRIM(phone),'')` 生成列，唯一索引 `uk_users_phone_key` 保证跨请求、跨实例唯一；不得只依赖业务层查询。注册改用普通 INSERT，唯一冲突后重新按手机号读取已有账号，不得把生成 ID 碰撞的其他账号当作登录用户。
- Mongo 使用排除空手机号的部分唯一索引；索引创建失败时拒绝手机号写入。内存仓储在同一锁内检查、写入，并复制用户对象避免引用绕过校验。
- 资料通用 `Update` 不修改手机号；所有绑定入口使用 `BindPhone`。公开入口必须先验证本人 JWT 和目标号码短信验证码；占用返回 409，不自动抢占或合并其他账号。未来增加第三方登录时仍复用此绑定规则。
- 短信验证码校验与消费在同一锁内完成。已删除账号的 JWT 校验失败，不回退为默认令牌版本。

## 已有 MySQL 升级

现有表的唯一约束由运维显式升级，不放入启动补列流程，避免重复数据引起初始化失败后降级内存。未安装索引时，已有账号仍可短信登录，新手机号注册和绑定返回 503，其他资料操作不受影响。

1. 备份数据库，在一致性快照中检查非空手机号格式、首尾空白及 `TRIM(phone)` 重复分组。
2. 重复账号由业务明确主账号；暂停应用写入后再次核对。合并必须保留轨迹及删除状态、收藏、成就、关系、设备、权限与登录记录；重复关系去重。私信需要处理会话 ID、消息 ID/幂等哈希、序号、已读边界及会话摘要，不能仅替换 user_id。推荐画像等派生缓存失效后重新生成；历史埋点身份不改写。
3. 在事务中迁移关联数据并删除旧账号，提交前检查目标数量与旧账号残留引用。失败回滚。保留主账号资料，更新最近活跃时间；旧 MQTT 会话撤销。
4. 确认无重复后单独执行（DDL 会隐式提交，不放入合并事务）：

   ```sql
   ALTER TABLE users
     ADD COLUMN phone_key VARCHAR(32)
       GENERATED ALWAYS AS (NULLIF(TRIM(phone), '')) STORED,
     ADD UNIQUE KEY uk_users_phone_key (phone_key);
   ```

5. 启用修复后的服务，核对 MySQL 仓储、唯一索引、手机号唯一归属及迁移数量。旧账号需要重新短信登录主账号；私信页面重新进入以读取合并后的序号。

禁止自动删除某条重复记录。备份与含真实账号数据的操作计划仅保存在受限运维目录，不入 Git；先记录备份恢复方法，合并后避免直接全库回滚覆盖后续正常写入。
