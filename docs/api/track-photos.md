# 运动实拍

普通运动与同行房间拍摄的照片独立于轨迹几何和投稿配图。同行使用拍摄者本人的成员轨迹 ID。成员轨迹自动结算，照片由本人在结算页手动上传。KMZ、GPX 及公开轨迹预览图只包含轨迹资料。下列业务接口位于 `/api/v1`，均要求业务 JWT。时间戳单位为毫秒，坐标为 WGS84。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/track/:track_id/photos` | 本人向已结束轨迹提交一张照片 |
| GET | `/track/:track_id/photos` | 按拍摄时间返回当前浏览者可见的照片 |
| GET | `/track/:track_id/photos/:id/image` | 按同一可见性规则读取 JPEG |
| DELETE | `/track/:track_id/photos/:id` | 本人撤回照片 |
| GET | `/track/discover/scenic-spots/:spot_id/user-photos?cursor=…` | 已收录的用户实拍，每页最多 24 张，`is_mine` 标明当前账号是否为拍摄者 |
| GET | `/track/discover/scenic-spots/:spot_id/user-photos/:id/image` | 复核当前景点归属后读取 JPEG |

单张上传使用 `multipart/form-data`。`image` 部分直接传 JPEG 二进制，`metadata` 部分为 JSON，包含 `id`（客户端小写 UUID）、`slot`（本次录制 1–20 的固定位置）、`taken_at_ms`，可选 `description`（去除首尾空白后单行最多 20 个 Unicode 字符）。列表沿用照片可见性展示描述，空描述省略。有可靠定位时同时传 `latitude` 和 `longitude`。长边最大 800 px，客户端目标约 100 KiB，服务端接受最大 200 KiB 的 JPEG，解码并重编码以清除 EXIF。轨迹创建与照片上传分别确认。同一次请求重试复用原 UUID、位置、描述和图片内容，冲突返回 409。撤回释放位置并移除图像数据。

照片初始为 `pending`。本人可以读取待审、通过及驳回照片和驳回原因。其他用户只能读取已完成、正常公开、具有轨迹文件的轨迹内 `approved` 照片。数据和图片响应均禁止缓存。照片独立存储于受保护的业务仓储，列表查询只读取元数据。

后台「内容审核」保留路线投稿与轨迹照片两队列。照片以五条轨迹为一页，同一轨迹内每张均可单独审核。轨迹详情弹窗也可在缩略图下审核待审随拍，或打开大图调整已有结果，需要相同的内容审核操作权限。审核和撤销使用照片版本，驳回须填写原因，通过时清空历史原因。景点管理可从当前关联轨迹的已通过照片中收录或移除单张。

公开轨迹关联主景点后，该轨迹的已通过照片进入该景点的待选列表。景点相册及其图片接口只展示后台为当前景点明确选入的照片。规则同样适用于存量照片，过去仅凭拍摄点命中范围展示的照片转为待选，已有的人工选入继续生效。移出景点图库只改变景点展示。照片审核改为驳回会撤销收录，再次通过后需重新选入。每次查询均复核当前轨迹可见性、主景点和审核结果。
