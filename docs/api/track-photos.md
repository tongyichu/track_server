# 运动实拍

普通运动与同行房间拍摄的照片独立于轨迹几何和投稿配图。同行使用拍摄者本人的成员轨迹 ID。成员轨迹自动结算，照片由本人在结算页手动上传。KMZ、GPX 及公开轨迹预览图只包含轨迹资料。下列业务接口位于 `/api/v1`，均要求业务 JWT。时间戳单位为毫秒，坐标为 WGS84。

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| POST | `/track/:track_id/photos` | 本人向已结束轨迹提交一张照片 |
| GET | `/track/:track_id/photos` | 按拍摄时间返回当前浏览者可见的照片 |
| GET | `/track/:track_id/photos/:id/image` | 按同一可见性规则读取 JPEG |
| DELETE | `/track/:track_id/photos/:id` | 本人撤回照片 |
| GET | `/track/discover/scenic-spots/:spot_id/user-photos?cursor=…` | 已收录的用户实拍，每页最多 24 张 |
| GET | `/track/discover/scenic-spots/:spot_id/user-photos/:id/image` | 复核当前景点归属后读取 JPEG |

单张上传使用 `multipart/form-data`。`image` 部分直接传 JPEG 二进制，`metadata` 部分为 JSON，包含 `id`（客户端小写 UUID）、`slot`（本次录制 1–20 的固定位置）、`taken_at_ms`。有可靠定位时同时传 `latitude` 和 `longitude`。长边最大 800 px，客户端目标约 100 KiB，服务端接受最大 200 KiB 的 JPEG，解码并重编码以清除 EXIF。轨迹创建与照片上传分别确认。同一次请求重试复用原 UUID、位置和内容，冲突返回 409。撤回释放位置并移除图像数据。

照片初始为 `pending`。本人可以读取待审、通过及驳回照片和驳回原因。其他用户只能读取已完成、正常公开、具有轨迹文件的轨迹内 `approved` 照片。数据和图片响应均禁止缓存。照片独立存储于受保护的业务仓储，列表查询只读取元数据。

后台「内容审核」保留路线投稿与轨迹照片两队列。照片以五条轨迹为一页，同一轨迹内每张均可单独审核。审核和撤销使用照片版本，驳回须填写原因。景点管理可从当前关联轨迹的已通过照片中收录或移除单张。

景点相册动态关联有效主景点、公开轨迹、审核状态与拍摄点证据。有高德识别能力时，既有调度器在同一预算和租约内逐批检查公开照片的拍摄点，仅使用命中景点内部的 AOI 证据。仅邻近、缺乏可靠定位及缺少可信范围的照片可人工收录。人工选择按景点生效。改绑、下架和撤回会在后续列表与图片请求中重新校验。
