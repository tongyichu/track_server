# 后台省市筛选与用户地域统计

地区资料的新增、编辑和客户端目录协议见[地区目录](regions.md)；本页说明用户、景点列表的地域筛选及用户地域统计。

所有接口使用后台会话及对应模块查看权限；地域筛选在分页前执行，`total` 为完整筛选结果数量。

## 用户管理

`GET /admin/api/users` 增加可选 `province_code`，按用户资料省份精确筛选，与现有 `city_code` 取交集。两字段优先传地区目录 `region_id`；服务端兼容旧 adcode 存量记录。其他筛选、游标及响应字段不变。

## 景点管理

`GET /admin/api/scenic-spots` 支持可选 `province_code` 和 `city_code`。城市非空时优先按城市筛选，否则将省份展开为省内城市编码及省级编码本身。

匹配目的地自身 `city_code` 或任一仍存在的关联轨迹 `city_code`；与列表城市展示保持相同关联轨迹范围，不额外排除私密、进行中或软删除轨迹。无地域条件时沿用原目录行为。与 `q`、`missing`、`status` 等条件组合使用，筛选不调用地图供应商。

MySQL、Mongo、内存实现均在总数统计及游标分页前应用地域条件，不限于浏览器已加载的前 100 条。

景点列表统一先按景区等级 5A→4A→3A→2A→1A→未知排列，同级按 `related_track_count` 降序，数量相同按景点 ID 升序；完整条目与 `view=summary` 使用相同顺序。轨迹数沿用后台“相关轨迹(N)”的完整关联范围，只排除已经不存在的轨迹，不改为 App 的公开已完成口径。服务层按每批最多100个扫描全部匹配目录并批量关联计数，完成全局排序后再截取请求页；同一批统计同时用于排序和当前页数量/省市展示，不逐景点请求或重复补计数，不调用外部服务。`total` 是筛选后的完整数量，`next_cursor` 仍是不透明使用的末项景点 ID，下一页从当前排序中的该锚点之后继续；不再按 ID 大小截断候选。末页 `has_more=false` 且 `next_cursor` 为空，整页恰好达到limit也不会误报有下一页。锚点已删除或不再符合筛选时返回400，需清空游标重新查询。

### 景点目录轻量摘要

目录页请求 `GET /admin/api/scenic-spots?view=summary`，不传view保留完整条目，总数、地域/缺项筛选及全局排序/游标不变。另提供手动关联用view=picker：q必填且≤160字符，仅active、禁止status/missing，最多20项，按ID游标读取单页，返回items（id/name/related_city_labels）、has_more、next_cursor，不返回total或统计、不全局排名、不读关联轨迹。均沿用景点查看权限和no-store；其他view返回400。详见[手动录入景点](admin-tracks.md#手动录入景点)。

summary条目仅包含：

| 字段 | 说明 |
| --- | --- |
| id / name | 景点编号与名称 |
| scenic_grade | 已保存景区等级，无等级可省略，页面显示“-” |
| related_city_labels | 景点自身及仍存在关联轨迹的省市名称，去重排序，如“陕西省 · 西安市”；直辖市不重复显示。按当前地区目录快照和兼容编码解析，不猜省份；解析不到保留已有城市名 |
| photo_count | photos数组长度，无图片为0，不下载或核验图片，不因封面地址单独存在而增加计数 |
| edit_mode | manual / automatic；与原页面的人工编辑标识、有效来源及同步状态判断一致 |
| related_track_count | 完整关联轨迹数，沿用原有范围 |

列表不再携带分类、简介、图片数组/URL和来源详情；不创建缩略图节点。详情接口及编辑字段保持完整，点击查看后按原流程加载。相关轨迹的计数与城市复用服务层批量排序统计的当前页数据，省市格式化只读既有地区快照，不逐景点查询或调用供应商。三种仓储复用同一后台摘要组装，不改变表结构或仓储接口。


## 用户地域统计

`GET /admin/api/users/statistics` 使用后台 users 查看权限，返回全量用户画像统计，不随下方列表筛选变化。性别、星座、年龄及轨迹产出字段保持原有格式；`user_cities` 使用专用城市结构，替换原先的通用 `key/label/count` 项：

| 字段 | 说明 |
| --- | --- |
| `region_id` | 城市或直辖市的内部地区编号，未知项为空字符串 |
| `name` | 目录名称，未知项为“未知城市” |
| `country_code` | 目录国家根节点的国家代码，如 `CN`；未知项省略 |
| `province_id` / `province_name` | 从目录父子关系解析的省份内部编号及名称，存在时返回 |
| `province_map_code` | 国内省份的高德 adcode，仅用于匹配内置省份地图，与业务内部编号分开 |
| `count` | 当前所在该城市的用户数 |

三种仓储统一按用户资料 `city_code` 聚合，不使用轨迹数据。后台读取一次权威地区目录，将旧树键、旧 adcode 和当前 `region_id` 解析并合并为同一内部城市编号，再返回国家、省份及地图字段。国家取目录国家节点，省份取目录祖先节点；省份地图编号优先使用显式 `amap/adcode`，再兼容目录原 `cn_adcode`。不根据城市编号的位数、前缀或地图匹配失败推断海外。

前端统计卡片名为“用户位置分布”，国内城市按 `province_map_code` 汇总。初次加载不自动选中省份，下方按用户数降序展示省份 Top 10；点击省份后按 `region_id` 展示该省城市 Top 10，点击地图省份外的空白区域清除选中并恢复省份 Top 10。刷新保留仍有数据的已选省份，未选中时继续展示省份榜。只有明确非 `CN` 的地区计入海外城市人数及城市数。空值或无法识别的编码合并为未知城市；国内已知城市缺少省份地图映射时，页面暂计入未知项，避免丢失人数或计入海外。历史已归档目录节点仍可用于解释已有用户记录，不执行用户资料迁移或回填。目录读取失败返回503，前端保留上一次统计并允许刷新重试。

## 页面级联

两个页面通过 `GET /admin/api/cities` 获取省市编码、名称和层级。选择省份后清空旧城市选择、收窄城市选项并重新查询；清空省份恢复全部选项。保留直辖市省级编码选项。省市筛选不会改变页面顶部统计的原有统计范围。

景点图片编辑后的完整条目新增只读photos_edited字段，由服务端根据真实相册编辑维护，不能靠客户端提交来清除。后台轻量摘要不传此字段，photo_count仍为目录photos数组长度（可含等待迁移的旧外链），不代表客户端下载成功数量；相册后台同步与App仅展示本站图的边界见[景点图片独立巡检](../track-place-discovery.md#景点图片独立巡检)。
