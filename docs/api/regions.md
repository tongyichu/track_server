# 地区目录

地区目录是客户端选城和后台地区资料的唯一数据源。服务端首次启动且存储中没有目录时，从 `internal/regions/seed.json` 导入国内省市；这份初始数据来自 Android 端原有 JSON，保留 34 个省级编码、337 个城市编码、全部经纬度和已有坐标状态。此后只读取数据库中的目录。国内现有树节点 `id`、外部编码 `code`、层级与父级保持稳定。目录协议仍保留邮编与 `active` 字段，已有值在后台保存时保持不变；新建节点默认 `active: true`。

城市业务字段统一使用 `region_id`：国家根节点是两位国家缩写（如 `CN`），该国家下所有省、市和其他节点共用六位递增序号（如 `CN000003`），序号不按层级分段。已分配编号不可改、不可复用，新增节点只取该国家已有序号的最大值加一。旧目录首次读取时按既有节点存储顺序补齐编号并保存新版本。`id` 和 `parent_id` 仍是目录树的旧稳定键，供旧目录及管理页兼容，不作为新业务记录的城市编号。

第三方地区标识存在节点的 `external_ids` 数组，每项为 `{provider,type,value}`，当前管理页支持 `amap/adcode` 和 `google/place_id`；同一个来源、类型和值不能指向两个节点。旧 `code_system=cn_adcode` + `code` 无需批量迁移，服务端自动视为高德映射并继续保留作历史兼容。Google 地区 Place ID 与景点 Place ID 分开记录，不能互用；Google 标识可能变化，管理员可更新映射。外部标识只用于解析到 `region_id`，不替代内部编号。

## 客户端读取

`GET /api/v1/regions/catalog`，需要 Bearer token。首次读取返回完整目录；可传 `known_version=<本地版本>`。如果版本一致，响应只包含版本和 `unchanged: true`，否则返回完整节点列表。客户端先读取私有目录中的 `region_catalog.json`，再检查服务端版本；下载成功后原子写入本地文件。无网络时继续使用已有文件。后台保存后版本递增。

完整响应示例：

```json
{
  "code": 0,
  "data": {
    "version": 1,
    "nodes": [
      {"id":"country:CN","region_id":"CN","parent_id":"","name":"中国","level":"country","code":"CN","code_system":"iso3166-1","country_code":"CN","continent":"AS","selectable":false,"active":true,"sort_order":0},
      {"id":"cn:330100","region_id":"CN000118","parent_id":"cn:330000","name":"杭州市","level":"city","code":"330100","code_system":"cn_adcode","country_code":"CN","latitude":30.246026,"longitude":120.210792,"selectable":true,"active":true,"sort_order":83}
    ]
  }
}
```

`nodes` 是完整树。字段包括 `id`、`region_id`、`parent_id`、`name`、`name_en`、`level`、`code`、`code_system`、`external_ids`、`country_code`、`continent`、`postal_codes`（字符串数组）、`slogan`、`description`、`photos`、`latitude`、`longitude`、`coordinate_status`、`selectable`、`active`、`sort_order`。可选字段可能缺省，未设置的 `external_ids`、`photos` 可省略。`photos` 为有序图片数组，每项包含 `id`、`url`、可选 `caption`、`alt_text`；旧图片的 title、attribution、source_url、license、license_url、provider 元数据保留，后台不展示来源。单节点最多20张，说明最多500字，URL只允许HTTPS或本站地区图片路径。旧独立 `cover_url` 字段仍在首次读取时移除并递增版本，不再删除 `photos`。只有本身和祖先均启用、且 `selectable=true` 的节点进入客户端城市选择器。客户端以 `region_id` 写入用户和轨迹的 `city_code`，旧 adcode 和目录键仅在兼容读写时解析。国外层级由后台按国家下的任意树结构组织。

版本未变化时：

```json
{"code":0,"data":{"version":1,"unchanged":true}}
```

## 后台管理

`/admin/regions.html` 显示为“城市管理”，使用后台会话和独立的城市管理权限。国家以顶部标签切换，末尾的加号新增国家；每个国家内的下级节点以可折叠连线树呈现，有下级的节点默认折叠。节点的内部 ID 紧随名称，以较小灰字显示。地区资料提供高德 adcode 和 Google 地区 Place ID 输入；老国内节点的原 `code` 保留，修改高德字段可增加新的映射，不会抹掉旧编码。页面不提供邮编、启用状态、归档、层级、上级地区、编码体系和排序值的直接编辑；所属洲只在国家节点显示。省份和城市详情支持上传JPG/PNG/WebP、编辑图片说明、拖动排序、移除图片。新节点先保存基本信息后再添加图片；上传/导入完成后自动通过独立图片接口保存关联，删除、排序及说明也独立保存，不提交文字草稿。移除只解除关联，不物理删除文件。新增下级时固定父节点，国内按父级推断层级，其他地区默认为城市层级；排序值在同级末尾生成。页面按节点单独保存，切换节点时保留其他未保存草稿；未保存的新节点仍可删除。顶部不再显示目录版本、重新加载和保存全部修改按钮。

已保存的单个节点可点击“AI 联网填写”：服务端使用 Moonshot 联网资料生成英文名和简介草稿，并单独检索城市宣传口号。首选真实存在、流行或经典且有地域辨识度的旅游或城市形象宣传语；官方发布不是必要条件，长期使用和传播情况优先。仅当检索来源标题或正文中能核对口号原文时返回 `slogan` 和 `slogan_source_url`；首轮未找到可核实口号时换方向补充检索一次。不得创作口号、伪造来源或把历史口号冒充现行官方口号。AI 查询只返回文字草稿和资料来源，不会批量执行或自动写入目录。管理员可只代入空白文字或覆盖文字，仍需点击“保存当前节点”才生效。

普通资料、口号检索和文字整理依次调用 Moonshot；首轮无可核实口号时增加补充检索和简短整理，因此这类请求会更慢。同一服务进程内的地区查询串行占用 Moonshot 请求槽；遇组织并发上限返回的 429 时短暂退避重试。文字整理使用 Kimi JSON 模式，单次等待响应最多 45 秒，超时且请求仍有效时重试一次。服务端 `[RegionResearch]` 日志记录普通资料、口号及文字整理各阶段耗时，不记录模型生成的正文。若模型输出被截断，管理页会提示重试。

| 方法与路径 | 权限 | 用途 |
| --- | --- | --- |
| `GET /admin/api/regions/catalog` | 查看 | 读取完整目录和版本 |
| `PUT /admin/api/regions/catalog` | 操作 | 以 `{version,nodes}` 保存完整目录；版本不匹配返回 409 |
| `PUT /admin/api/regions/node` | 操作 | 以 `{base_node,node}` 保存单个节点；`base_node=null` 新增，当前节点与基线不一致返回 409，返回最新完整目录 |
| `DELETE /admin/api/regions/:node_id` | 操作 | JSON `{expected_version}`；仅非中国国家根节点，将该国及全部下级 `active` 置为 false，返回最新完整目录；版本变化409，中国/非国家节点400 |
| `POST /admin/api/regions/research` | 操作 | JSON `{id}`，已保存的目录树节点 ID；返回文字草稿和资料来源 |
| `POST /admin/api/regions/:node_id/photos` | 操作 | multipart `file`、可选 `caption`；仅已保存省份/城市，JPG/PNG/WebP≤8MiB、尺寸≤12000×12000，返回 `{photo,image_info:{width,height,size_bytes}}`，不修改节点或目录版本 |
| `PUT /admin/api/regions/:node_id/photos` | 操作 | JSON `{base_photos,photos}`（均必填数组，可传空数组清空）；独立保存图片关联、说明和顺序，返回 `{node,version}`，图片基线冲突409，不提交文字资料 |
| `POST /admin/api/regions/photos/pixabay/search` | 操作 | JSON `{query,page}`；关键词1至100字，页码1至167，每页最多3张真实横版照片，返回 `{query,page,has_more,candidates:[{id,preview_url,source_url,author,tags}]}`；ID为字符串 |
| `POST /admin/api/regions/:node_id/photos/pixabay/import` | 操作 | JSON `{query,page,id}`；仅接收24小时有效查询缓存中的候选ID，服务端下载API原始地址并等比缩至960×720以内落盘，返回 `{photo}`，不保存节点或改变目录版本 |

后台完整目录响应（读取、完整保存、单节点保存和删除国家）在客户端接受 gzip 且正文至少 1KiB、压缩有效时使用 `Content-Encoding: gzip`，JSON字段和版本语义保持一致；始终返回 `Cache-Control: no-store` 与 `Vary: Accept-Encoding`，不进入公共静态资源缓存。城市树按节点ID和父节点建立内存索引，同级排序在目录更新或名称变化时重算；同一国家内切换已展开节点只更新选中状态，简介、口号等非树字段输入不重建树。

图片落盘到 `static/regions/<region_id>/<随机ID>.<jpg|png|webp>`，客户端资源地址为需业务JWT的 `/api/v1/static/regions/*`；后台预览改写为 `/admin/api/static/regions/*`，仅允许地区查看权限或管理员读取。上传走地区操作权限与既有同源/审计中间件，不新增图片表，MySQL/Mongo/内存均使用既有目录JSON存储。

省份和城市的图片区统一叫“宣传图片”。已保存节点支持多选后自动上传，每次最多并行两张，真实进度与上传失败重试显示在图片遮罩，右上圆圈叉移除并取消在途请求。每张成功后自动通过图片PUT接口保存关联，无需点击“保存当前节点”；删除、排序自动保存，说明在失焦后保存。新节点先保存基本信息再开放上传和Pixabay查询。每节点最多20张，保存中显示状态，失败保留本地修改并可重试；切换节点保留失败草稿，关闭页面不弹浏览器离站确认。

### 图片自动保存

图片项结构为“缩略图 → 像素尺寸和文件大小 → 说明输入框”，如`960 × 640 px · 180 KB`，取消左右移动按钮，保留拖动排序。省市上传与Pixabay导入的响应新增只读 `data.image_info={width,height,size_bytes}`；Pixabay使用最终缩图文件的信息。历史本站图片通过受鉴权的图片资源地址加 `?photo_info=1` 读取，无需重传或迁移；外链图片可读取实际显示尺寸，文件大小无法可靠获取时显示未知。这些信息只用于显示，不进入照片数组、图片基线或目录保存请求。

`regions.Service.SavePhotos` 只比较目标节点的 `base_photos`，在最新目录上替换 `photos`，复用目录版本CAS及MySQL/Mongo/内存Store；文字与其他节点不会被覆盖。照片基线不符返回409，目录CAS冲突最多重读4次；最新照片已等于目标时视为幂等成功。前端只更新文字编辑基线中的照片字段，保留其他文字基线，避免同时发生的远端文字改动被错误覆盖。图片操作不标记文字表单dirty，基础资料仍经原节点接口保存。

共享图片编辑器串行提交有序快照；保存期间的新上传、移除或排序在前一请求确认后继续提交。已完成图片可以独立保存，不因其他图片上传失败而丢失。说明输入保留草稿，仅失焦提交；并发上传完成不提交尚在输入的说明。状态区显示保存中、已自动保存、失败及重试；也可放弃本地图片修改后重新打开核对。保存请求30秒超时，切换/销毁忽略旧回调并取消请求；城市管理页不拦截离站，不弹浏览器确认。上传/导入接口仍只暂存文件，自动PUT成功才表示关联入库；移除不物理删除文件。两端均沿用模块写权限、同源校验和审计。

### Pixabay 人工选图

服务端配置可选 `PIXABAY_API_KEY`（仅在 `internal/config/config.go` 读取，未配置时查询返回503明确提示）。省份/城市“宣传图片”标题旁提供“从 Pixabay 查询”，点击才发起查询；优先使用当前节点英文名，否则使用中文名，可改关键词、换一组，每组最多3张，不后台遍历省市或自动翻页。查询区显示 Pixabay 来源链接和候选原始页面；默认不勾选，可“导入所选”或明确点击“全部导入”。搜索时切换节点/关闭查询区取消请求并忽略旧响应，失败保留上一组。

同一查询、页码、固定筛选的上游响应在 `<LogDir>/pixabay-cache` 私有文件缓存24小时，重启后复用；最多512份有效缓存，不淘汰有效缓存来重新请求。每进程下载任务最多2并发（含回退），查询限1并发、限速且受供应商429约束；每次图片传输超时30秒、单图≤8MiB，只接受服务端缓存中的ID和受限Pixabay HTTPS域名/重定向，拒绝客户端任意URL。API key和完整供应商请求URL不写日志、不下发前端。查询/导入均走地区写权限、同源及发起/结果审计。没有定时任务或目录读取触发的外部请求。

候选预览临时使用API的640档；导入保留API返回的签名地址原样，优先 `largeImageURL` 的1280档，旧缓存缺少该字段时使用原始 `webformatURL` 的640档，不因此提前刷新24小时缓存。虽然供应商文档提到替换尺寸后缀，实际 `/get/` 签名地址替换后会返回400无效/过期，因此禁止自行改写后缀。下载后等比缩至960×720以内，不放大小图，JPEG缩图质量80、PNG保留格式和透明度；不下载原图，不永久使用供应商链接。资源经过JPG/PNG、尺寸/大小校验后原子落盘到 `static/regions/<region_id>/pixabay-<图片ID>.<jpg|png>`。返回Photo保留 `provider=pixabay`、原始页面 `source_url`、作者 `attribution`、许可名及许可链接，原有图片项不显示来源。前端按候选ID/来源去重，确定性图片ID避免重复文件；文件完成后通过图片PUT自动保存关联、排序和说明，不新增图片表或改变仓储实现。下载失败日志只记录图片ID、阶段和HTTP状态，不记录签名地址或密钥。

导入复用现有队列、顺序、移除取消和失败重试，图片遮罩显示不确定进度的“正在下载并存储”，不伪造服务端下载百分比；完成后遮罩消失并自动保存图片关联。新节点须先保存基本信息再查询选图。缓存过期或图片不可用返回410，需移除该项并重新查询；503表示配置不可用，429提示稍后重试，其余下载/供应商错误返回502。导入接口成功只表示文件暂存，状态区显示“图片已自动保存”才表示关联确认入库。

大图传输/处理失败时，如同一缓存中有不同的原始640地址，最多回退一次下载小图，不再请求搜索API、不改写URL，已取消的父请求不回退。两次传输各限30秒，最多约60秒，仍受前端120秒请求上限约束；小图不放大。传输中断、超时、空内容和超过8MiB分别提示，不将所有读取错误误报“大小无效”。失败日志记录图片ID、阶段、原因分类、读取字节数、声明长度和耗时；不记录完整错误URL或密钥。

国外可新增国家和任意下级节点。新国家须填写两位国家缩写，保存时由服务端分配不可变 `region_id`；新增节点的目录树 `id` 仍由管理页生成，仅用于父子关联。本次编辑中未保存的新节点可以直接移除。

已保存的非中国国家在国家详情右上角显示实心“删除国家”按钮，仅城市管理操作权限可用。确认框显示下级数量及未保存草稿丢弃提示；通过独立DELETE将该国及全部下级归档（`active=false`），从国家标签和客户端选城目录移除，保留稳定编号、历史用户/轨迹引用及图片文件。中国及其下级在服务端禁止通过此入口删除；不支持用该接口单独删除省市。请求使用目录版本CAS，任何并发目录修改均返回409且不自动重试。删除成功后清理该国本地草稿与图片编辑会话、切换到剩余国家，其他国家的文字草稿保留；失败保留原编辑内容。已有通用保存接口仍不允许物理移除已保存节点。

MySQL 使用 `region_catalog_state` 单行 JSON 与版本号；Mongo 使用同名集合；本地内存模式只在当前进程有效。单节点保存读取最新目录后合入当前节点，对该节点做基线冲突检查；目录 CAS 冲突时重试，不覆盖其他节点的修改。
