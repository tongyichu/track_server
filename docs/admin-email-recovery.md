# 后台邮箱验证与密码找回

## 当前接入状态

2026-11-01 只读检查生产配置：已有阿里云 OSS/STS 配置，没有 SMTP/邮件服务配置；系统 Postfix 未启动且没有邮件中继。不能把已配置 OSS 等同于已开通邮件推送，也不调用本地 sendmail 作为回退。本轮实现通用加密 SMTP，可接阿里云邮件推送或已有企业邮箱；没有开通云产品、修改生产配置或发送验证邮件。

## 配置发信服务

1. 在邮件服务商准备发信域名和发信地址，完成服务商要求的 DNS 验证。建议使用专门的发信子域名，例如 `notify.example.com`，不要直接填写尚未验证的地址。
2. 为发信地址设置独立 SMTP 凭证。阿里云邮件推送的 SMTP 用户名就是发信地址，使用该地址的 SMTP 专用密码；不是 OSS AK/SK，也不是阿里云控制台密码。参考[阿里云 SMTP 文档](https://help.aliyun.com/en/direct-mail/user-guide/send-emails-using-smtp)和[发信域名配置](https://www.alibabacloud.com/help/en/direct-mail/domain-name-configuration-faqs/)。
3. 按 [配置模板](../deploy/admin-email.env.example)将配置写入受保护、Git 忽略的生产 `.env`，真实密码不得写进仓库、聊天、命令参数或日志。当前单容器部署通过 `--env-file` 注入；更新配置后需要在获得部署授权时重新创建服务容器。

| 配置 | 含义 |
| --- | --- |
| `ADMIN_SMTP_HOST` | SMTP 主机名；阿里云示例为 `smtpdm.aliyun.com`，其他地域/服务商按对应控制台为准 |
| `ADMIN_SMTP_PORT` | 默认 465 |
| `ADMIN_SMTP_TLS_MODE` | 默认 `tls`（连接即 TLS），或 `starttls`（必须升级 TLS）；证书必须通过验证，最低 TLS 1.2 |
| `ADMIN_SMTP_USERNAME` | 专用 SMTP 用户名 |
| `ADMIN_SMTP_PASSWORD` | 专用 SMTP 密码或授权码 |
| `ADMIN_SMTP_FROM` | 经过服务商验证的发信地址，纯邮箱格式 |

配置全部缺失时邮件功能保持关闭，不影响后台登录和原密码修改；部分缺失或非法时同样关闭，并输出不包含凭证的配置告警。页面通过能力接口显示暂不可用，不伪造发信成功。SMTP 接受邮件不等于最终收件箱送达，投递/退信问题需在邮件服务商查看。公开找回申请始终返回相同通用提示，不通过返回值透露账号或邮箱是否匹配。

## 用户流程

- 本人进入齿轮菜单的“账号安全”（保留 `/admin/password.html` URL）。可用当前密码直接修改本人密码，也可绑定并验证找回邮箱。临时密码账号必须先完成改密，再绑定邮箱。
- 首次绑定：输入当前密码和新邮箱，接收新邮箱的 8 位数字验证码，验证后保存；仅输入地址不算绑定。邮箱不能与其他账号已验证的邮箱重复，管理员不能替其他账号设置邮箱。
- 更换邮箱：输入当前密码，先获取原邮箱验证码，再用原邮箱验证码申请新邮箱验证码，最后验证新邮箱。原邮箱验证通过但新邮箱未通过时，原邮箱仍是有效找回地址。原邮箱无法收信时不能绕过验证直接换绑，需要运维通过独立渠道人工核实，当前页面不提供绕过入口。
- 忘记密码：登录页进入 `/admin/forgot-password.html`，提交登录名和事先验证的邮箱，收取验证码后设置并确认新密码；不会发送原密码或明文新密码。成功后使用正常登录流程登录，不自动签发登录会话。
- 邮箱绑定/更换、本人改密和邮箱找回成功后，全部旧会话和所有旧验证码失效。邮箱更换通知新旧邮箱，密码变更通知已验证邮箱；通知为有界队列中的尽力投递，通知失败不会把已完成变更误报失败。

## 持久化与限制

邮箱、验证时间、各用途验证码摘要、有效期、错误次数及发信冷却都保存在现有 `admin_account_state` JSON 中，沿用 MySQL/Mongo 整体 CAS；无新表、无内存账号或验证码回退。验证码明文只在发送请求内存和邮件中出现，不写数据库、响应或日志；摘要使用随机盐、用途、登录名、验证码及服务端密钥做 HMAC-SHA256，验证时恒定时间比较。密钥从 SMTP 专用密码以独立用途派生，不写账号库，避免仅取得数据库读取权限就能离线穷举短数字码。三个用途（原邮箱、新邮箱、密码找回）分开，不能相互替代。

各实例需要一致的 SMTP 凭证配置；轮换 SMTP 密码会让旧验证码失效，用户需要重新申请。旧版本程序不认识这些新增 JSON 字段，直接降级后再写入账号状态可能丢失邮箱和挑战信息；回滚前需保留账号状态备份并评估旧版本写回，不将“没有新表”等同于可随意回滚。

- 验证码 10 分钟有效、一次使用；每个验证码累计 5 次错误即失效，错误计数通过 CAS 保存，不能因返回错误而丢失。改密、停用或成功验证会使关联挑战失效。
- 每个账号每个用途最少间隔 60 秒，共用每小时 10 封的持久化上限。该限制跨进程有效，修改密码不能重置发信配额。
- 公开找回申请：按 socket peer IP 每小时 10 次；提交验证码：每 IP 每分钟 30 次、每进程最多同时处理 2 次完成请求；登录态申请邮箱验证每 IP 每 10 分钟 30 次。IP 限制为进程内固定窗口，最多保存 4096 个条目；不信任客户端转发头。若之后加反向代理，需要结合可信代理配置评估共享出口限额，不直接信任任意 X-Forwarded-For。
- 公开申请先进入最多 16 条的队列，再由两个 worker 查库并发送，避免匹配/不匹配账号因同步 SMTP 产生明显的响应差异。SMTP 总并发最多 2，设置连接与操作超时，没有无限制 goroutine。发信队列本身不持久化，重启期间尚未处理的申请需重新提交；已保存的挑战和限额持久化。
- 账号数据库不可用时不能完成任何邮箱或密码变更，不能恢复为环境变量登录；公开通用申请被接收不表示已通过账号匹配或已投递。

## 管理员重置迁移

已验证找回邮箱的账号不再提供管理员重置按钮，服务端也直接拒绝代重置。尚未绑定的账号暂保留明确标注“应急重置”的迁移入口，防止现有账号在新功能可用前失去恢复渠道；旧接口只在此条件下可用。

全部启用账号完成验证后，在持久化状态写入 `legacy_password_reset_disabled=true`，永久关闭旧管理员重置入口；之后新增未绑定账号或邮件服务暂时不可用都不会自动重开。新增账号仍使用临时密码首次改密，首次登录后应及时绑定本人邮箱；未绑定账号无法通过邮件找回。停用但未绑定邮箱的旧账号应在迁移关闭前妥善完成安排，不能把邮箱找回当作身份核验的替代。

账号列表只展示邮箱是否验证和迁移期是否允许重置，不给管理员下发完整邮箱或验证码信息；本人邮箱仅通过本人 `GET /admin/api/security` 读取。更新账号资料/权限的请求不接受邮箱或密码覆盖。

## 审计与验收

本人邮箱操作复用现有受保护写操作审计；公开密码找回完成接口单独保存发起和 HTTP 结果，日志不可用时拒绝修改密码。未登录找回的 actor 标为 `email-recovery`，用户名为目标账号，页面显示“邮箱找回（未登录）”，不能把失败申请认作账号本人操作。日志中不保存邮件正文、邮箱地址、验证码、密码或摘要；公开申请发送邮件不作为登录或密码变更成功记录。

发布前按照项目约定只做构建、JS 语法和源码自查。部署后由用户手动确认首次绑定、旧/新邮箱换绑、正确/错误/过期验证码、连续错误、重复提交、改密/停用后旧码失效、迁移入口关闭、收件箱与垃圾箱投递、并发请求和两种数据库环境；默认不运行接口或浏览器自动化，不用真实账号发送测试邮件。生产后台应使用 HTTPS，不能因为 SMTP 已加密就认为浏览器链路也受保护。
