# 轨迹形象标签

读取 [共享识别规则](references/shape-rules.txt)，按完整轨迹轮廓及关键部位判断形象。候选包括动物、花草、地标建筑、数字、地图轮廓（如中国地图）、人物头像、节庆及生日图案，类别不是强制选择列表。

## 输入与判断

- 只看一张实际 1:1 轨迹预览图，并参考用户标题。图片无法读取时说明无法判断，不能从标题或空标签推断视觉结论。
- 按一笔画、简笔画标准判断；先独立看整体，再验证标题或用户提出的候选。允许道路折线、比例简化和不影响判断的局部遮挡，不要求写实。
- 优先组内同等检查动物/生肖、花草、地标建筑、数字、地图、人物头像、节庆生日及组合图案，不以动物为首选或只查首个联想。每类可无候选；完成组内检查后再比较其他类别。用整体覆盖、关键部位对应及牵强程度比较，难以区分时留空。诊断给简短分类依据，不输出冗长推理。
- 依据共享规则输出简短名称及 shape_confident、shape_appropriate；没有明确且适宜的形象时名称为空。向用户解释时指出可见部位和不确定性，不编造模型原始理由。
- 普通名称优先，不猜动物品种、具体人物身份，也不把地图或建筑形象当成路线实际位置。

## 组合图案

新年跑可能画生肖与年份，生日跑可能画数字、蛋糕或蜡烛。按共享规则核对各完整主体及组合布局，可输出“龙＋2026”“蛋糕＋30”等短名称，不强求整条线只像一个物体。只认出完整显著的主体时仅保留该主体，不能从零散局部硬凑。数字读图，不按标题、当前年份或生肖历法修正；不能把数字自动解释成年龄。用途须有可信资料支持。保持现有单个 `shape_label` 协议。

## 人工标注反馈学习

同时读取 [学习规则](references/learning-rules.txt)。管理员保存新增、修改或清空形象标签后，服务端记录最新修正（原标签、最近自动结果及是否存在、标题、预览源、操作人、时间、模型及规则版本），由后台轮转复核一张方图，不阻塞保存等待模型。

复核须独立说明可见部位如何支持或反驳人工标签，提炼适用条件或误判警示。旧模型未记录推理时只能说“可能漏识别的原因”，不能伪造其当时的思考。人工标注是反馈证据，不是让模型无条件同意的指令；图像不支持时记录分歧，保留人工标签，但不吸收为经验。人工清空也可提供避免误判的负例。

服务端把支持的结果写入动态经验层 `narrative:shape-memory`，近期最多8条，每次生成最多使用4条，每条可见依据与经验各不超过100字符。本轨迹最新反馈及复核状态保存于 `narrative:shape-feedback:<ID>`；再次修正替换该轨迹的最新反馈，旧经验立即停用。引用前核对公开状态、预览源及当前人工标签；修改、换图或下架使旧经验失效。自动经验不触发历史全量重跑，也不覆盖人工标签（包括清空）。每轮最多一个学习调用，与常规生成共享每轮3次和每日预算；失败最多3次并退避。

这是一份固定基础规则加动态案例经验的 skill，不是训练模型权重，也不是生产服务自行改写 Git 中的 SKILL.md。调整基础规则时复盘后台显示的案例依据，提炼可迁移的判断条件，不能只硬编码某个轨迹 ID 的答案。基础规则与适宜性限制始终优先于经验；不扩展为额外图片、KMZ 解析或联网搜索。

## 服务端维护

后台按钮必须走 `PreviewShape → TrackShapeGenerator.GenerateShape`，使用共享识别规则与 [专用形象输出契约](references/shape-only-output.txt)，不生成路线说明。调用参数为 `thinking.type=disabled`、temperature=0.6、max_tokens=8192。输入只含标题、基础统计、一张方图及最多4条有效经验，不带投稿或景区长文。服务端验证8类检查、候选及结论枚举，返回诊断依据并保存同源版本最近结果。自动路线说明与反馈复核仍走 Generate，不将二者的调用效果混为一谈。

验收后台按钮时应使用真实 `POST /admin/api/tracks/:track_id/labels/generate`，同时核对响应 diagnosis 与界面展示；独立 Python 提示词试跑仅为探索，不能称后台接口已验证。未部署时明确区分编译/静态检查与真实接口验收，不把单条轨迹识别成功推广为稳定准确率。

`references/shape-rules.txt` 与 `references/learning-rules.txt` 分别是识别与复核规则的唯一正文来源，由本目录 `rules.go` 嵌入，`internal/service/kimi_track_narrative.go` 拼入请求。只发送规则正文，不把本技能说明全文发送给 Kimi。

修改识别语义时同步递增 `internal/service/track_narrative_input.go` 的规则版本，并更新 `docs/track-narrative.md`。同一尚未部署版本内的连续调整可以保持版本号。保留一张图、一次调用及既有预算，不为枚举候选增加请求，不解析全部 KMZ 点。

修改技能不自动部署、不重跑生产任务、不写入人工标签。按仓库约定运行 `go build ./...`；线上识别效果需另行验证，不能把编译通过当作模型识别通过。
