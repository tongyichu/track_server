# 后台写入、续跑与核验

## 建清单与账本

以当前 `docs/api/regions.md`、`internal/admin/routes.go`、`internal/admin/regions.go`、`internal/admin/region_photos.go`、`internal/regions/catalog.go` 和 `internal/regions/photos.go` 为准，不把本文当成永久不变的接口定义。

从用户提供或项目已有部署配置确定目标环境和后台身份，不硬编码生产地址、账号密码。使用独立 admin session，写请求携带匹配目标站点的 `Origin`；cookie 留在权限受控的工作文件中，不输出到日志或提交仓库。登录路径为 `POST /admin/api/login`，不是业务 JWT 登录。

读取 `GET /admin/api/regions/catalog` 的 `data.version`、`data.nodes`，支持 gzip 解码。用实时目录生成本次授权范围的清单，不依赖 seed 或历史节点总数。分别记录：

- 地区树 `id`、稳定 `region_id`、全路径、缺失文字字段、现有完整照片数组。
- 新素材文件路径、尺寸、字节数、SHA-256、说明、来源和审核状态。
- 每次上传返回的完整 Photo、关联保存结果、文字保存结果和独立回读结果。

工作文件与图片交付目录分离，凭证另存。账本原子写入，批次按地区去重；恢复任务先读取账本和实时目录，不能因重启再追加相同三张图。多个研究者分开写候选，协调者合并审核；上传账本由一个进程维护，可用有限网络工作线程，例如 1–3 个。

## 图片：上传文件，再保存关联

1. 写入前再次读取当前节点，确认仍在范围内、旧照片数组和待追加数量。当前每节点上限 20 张；容量不足时报告，不为腾位置删除旧图。序号和说明应与此时的旧图数量一致。
2. 三张成品实际查看并审核后，对 URL 编码后的树 `id` 请求 `POST /admin/api/regions/<node_id>/photos`，multipart 字段 `file`、`caption`。当前单文件不超过 8MiB，返回 `data.photo` 与 `data.image_info`。**POST 只暂存资源，不关联节点**。每次成功立即持久化返回值和对应本地哈希。
3. 保留服务端返回的 `id`、`url`，按证据补充允许的 Photo 字段，如 `caption`、`source_url`、`attribution`、`license`、`license_url`。不可虚构作者/许可。尺寸/字节数仅写本地账本，不能塞进 Photo 基线。
4. 使用独立接口 `PUT /admin/api/regions/<node_id>/photos`：

   ```python
   payload = {"base_photos": old_photos, "photos": [*old_photos, *new_photos]}
   ```

   `old_photos` 是实时完整 Photo 数组，`new_photos` 是三张上传成功的新 Photo 数组；将 payload 编码为 JSON。旧图全部字段及顺序原样保留，不能仅按 URL 重建旧对象。不要用整节点或整目录覆盖来关联照片。
5. 独立 GET 目录，确认本节点有且仅有计划中的三项新增、原有图片及元数据未丢失。经同源 `/admin/api/static/regions/...` 下载新增资源，逐张 SHA-256 与本地成品一致，才计为图片完成。资源 URL 来自服务端，并校验位于本节点 `region_id` 路径内；不将带 cookie 的请求发送到外部来源网址。

后台资源地址由返回的 `/api/v1/static/regions/...` 改写为 `/admin/api/static/regions/...`，使用后台 session，不用 App JWT。

## 文案：用实时完整节点作基线

1. 每个节点保存前读取实时完整对象，重新判断指定字段是否空白。已被人工或其他任务填入的非空字段保留并记为跳过；口号缺证则不提交该字段。
2. 深拷贝实时节点，仅修改本次仍为空白且有审核结果的 `slogan`、`description`。请求 `PUT /admin/api/regions/node`，正文为 `{"base_node": 实时完整节点, "node": 修改后完整节点}`；已有节点的 `base_node` 不能为 null。
3. 验证响应中的目标字段和未修改字段，再独立 GET 目录核对。当前照片及其他元数据应保留，不能拿任务最初的快照覆盖后来人工修改。不使用 `PUT /admin/api/regions/catalog` 批量替换目录来回填文案。

图片与文字不是一个原子事务，分别记录状态；一项成功、另一项失败时如实报告并从未完成阶段恢复。

## 冲突、超时与停止条件

- GET 可有限退避重试。401 在现有授权身份下重新登录；403 停止相应写入并说明权限不足，不换接口绕过。
- 409 表示基线变化：重新读取并核对，只重做仍符合范围的改动，建议最多三轮；持续冲突保留待处理状态。照片数组变化时重新核对顺序、说明、容量及已上传 ID；不要覆盖新人工图或重复上传。需要调整本地命名时先撤回旧上传计划再审核。
- PUT 超时可能已经成功：先回读判断是否已达到预期，再决定是否重试。POST 上传超时且没有返回资源 ID 时，可能留下已接受的文件，停止该项自动重传，先按已有回执、目录及可用服务端记录核实；不能靠无限重试或自动删资源解决不确定状态。
- 检索失败、无清晰合法来源、缺少文案证据、格式不合格均作为独立未解决原因。不要为了完成率填入假文案或未经查看的图片。

## 最终核验与进度口径

按本次清单逐地区检查，不以 HTTP 200、候选数或上传成功数冒充录入完成。图片需关联回读与字节哈希一致，文案需字段回读一致；确认自己的保存未覆盖基线中的其他内容。任务期间可能存在外部修改，不能声称整个目录从开始到结束一字未变。

记录已核验图片地区数/目标数、已处理文案地区数/目标数、实际填入的各字段数、跳过已有内容数和未解决清单。文案“处理完成”可以包含有证据说明的保留空白项，但须与“实际补齐”区分。最终材料只放三张 WebP；核验 JSON、来源与账本留在独立工作目录，提供可点击路径以便复查。
